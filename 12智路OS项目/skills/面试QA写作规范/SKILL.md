# 面试 QA 写作规范

你面对的是一位**正在准备 C++ 开发岗面试的实习生**。他要的不是"技术文档"，而是**"面试官一问，我能张嘴念出来"**的稿子。

---

## 0. 和「面试笔记助手」的分工

| skill | 管什么 |
|---|---|
| 面试笔记助手 | **啃代码、讲项目、配 SVG 流程图**，产出学习笔记 md |
| 本规范 | **把项目经验写成面试题**，产出 / 维护 `0面试QA总表.md` |

**顺序：先啃代码 → 再写 QA。** QA 里每一句说法都要能在代码里找到依据（文件:行号），找不到就明说，绝不编。

## 1. 用户画像（决定你怎么写）

| 维度 | 事实 | 对你的要求 |
|---|---|---|
| 身份 | 实习生 | 全程说「**参与**」，绝不说"我从零设计" |
| 基础 | C++ 基础一般 | **大白话 + 类比**，别堆术语 |
| 状态 | 容易焦虑："内容太多记不住" | 主动做**减法**：区分"必背 / 储备 / 知道有这回事" |
| 习惯 | 常用 "ok" 表示收到 | 不必追问，直接执行下一步 |
| 偏好 | 喜欢用图理解结构 | 结构/层次关系配 SVG |

## 2. 三条硬标准（用户的原话，最重要）

1. **答案要更好理解、更好背、字数少一点**
2. **问题要从简单到深入**
3. **追问要有关联**——"面试官是听到你的回答里有疑惑才追问的，比如你提到用这个技术实现了什么，他就问这个技术是啥讲一下"

写任何一道题之前，先拿这三条卡一遍。

---

## 3. 每题的标准格式

````markdown
#### Qx-x 口语问题 [标记]

**答**：

（3~5 句，一段念完）

**追问**：从答里那个加粗的词接着问
> （2~3 句）

📌 *自己复习（面试别说）：函数名 / 字段名 / 路径*
````

细则：

- **问题用面试官的真实口吻**：他看不到代码，只会问「你怎么设计的 / 为什么 / 踩过什么坑 / 换你会怎么改」。
- **答案必须能张嘴念**：是口语段落，不是要点罗列；不要写成"第一 第二 第三"的汇报体。
- **函数名、宏名、字段名、文件路径一律不进嘴**，全部挪到 `📌 自己复习`。
- **普通题只留一条主追问**，不要堆三条；追问链靠跨题衔接来延伸。
  ⚠️ **例外：总览题必须做成编号追问链**，见 §6 末尾「特例：总览题要做成『追问链 + 导航』」。
- 需要提醒口径的地方，用 `> ❗ **误区：……**`、`> 💡`、`> 🔴` 三种标记，紧跟在对应答案之后。

## 4. 答案怎么写（重点：好背）

**硬指标**

| 项 | 要求 |
|---|---|
| 长度 | **3~5 句，约 120~180 字** |
| 念完 | **不超过 30 秒** |
| 结构 | 第 1 句给结论，后面补理由 / 例子 / 类比 |
| 分段 | 3~5 句合成**一个段落**，不要一句一行 |

**怎么做减法**

- 删掉铺垫句（"这个问题其实很复杂""首先要说明"）；
- 删掉和上一题重复的说明；
- 一个意思只说一次；
- 保留**结论 + 一个理由 + 一个类比**，其余砍掉。

**加粗的用法（很关键）**

- 只给两类东西加粗：**技术关键词** 和 **下一题要追问的钩子**；
- 不要整段加粗，否则背的时候没有重点。

**❌ 原来的写法（太长、书面、绕）**

> 如果直接在框架里写判断——是这个牌子就创建这个类的对象，是那个牌子就创建那个类的对象——那每来一个新厂商，我就要打开框架代码改一遍、再把整个框架重新编译一遍。框架是所有人共用的基础件，张三接入改一次、李四接入改一次，风险和协调成本都很高。还有一个更隐蔽的问题：这么写之后框架就依赖了所有具体驱动，随便哪个驱动改个头文件，框架都得重编。工厂模式把"选哪个设备"这个决策，从编译期推迟到了运行期，从代码里搬到了配置文件里。

**✅ 现在的写法（三句，念完 20 秒）**

> 不行，因为那会让主循环跟每一类检测器**绑死**。如果写 if-else，加一类检测器就要打开主循环改一遍，改八类主循环就膨胀成一团，谁都不敢动。用抽象基类之后，所有检测器在**主循环眼里长得一样**——都是"喂一帧进去、让它出一次数"这两个动作，所以主循环能一个 for 循环统一调度。

## 5. 问题怎么排序（由浅入深）

每个技术点内统一走这**五阶段**：

```
① 是什么（这模块干嘛 / 整体怎么设计的）
② 怎么做 / 为什么这么做
③ 细节和容易答错的点
④ 底层原理（八股：虚函数表、锁、容器…）
⑤ 有什么不足 / 换你会怎么改
```

**示例（条目四技术点 1）**

| 序 | 阶段 | 题 |
|---|---|---|
| Q1-1 | ① 是什么 | 检测服务整体上怎么设计 |
| Q1-2 | ② 为什么 | 为什么用抽象基类 + 工厂，if-else 不行吗 |
| Q1-3 | ② 怎么做 | 工厂具体怎么造出检测器 |
| Q1-4 | ② 设计 | 基类接口为什么只有两个 |
| Q1-5 | ③ 细节 | 「逐帧累积、到点结算」是什么意思 |
| Q1-6 | ③ 易错 | 一共几类检测器（诚实口径题） |
| Q1-7 | ③ 细节 | 车道级和断面级怎么分开 |
| Q1-8 | ⑤ 改进 | 有什么不足 / 怎么改 |

**跨技术点也要由浅入深**：先"框架整体"，再"数据怎么流进来"，最后"最底层的判定算法"。

## 6. 追问怎么设计（★★ 用户最看重这一条）

### 唯一规则

> **追问的主语，必须是上一句答案里刚刚出现的那个词。**

面试官看不到你的代码，他只能从你的回答里抓"没听懂的词"来追。所以：

- 答案里提到**某个技术** → 追问就问"这个技术是什么、讲一下"；
- 答案里做了**某个选择** → 追问就问"为什么不用另一种"；
- 答案里给了**一个数字 / 现象** → 追问就问"那会怎么样 / 怎么定位"。

### 三种标准套路

**套路 A：技术名词 → 讲一下**

> **答**：……上游感知结果通过 **Fast-DDS** 推给我……
> **追问**：Fast-DDS 是什么？跟你们另一套中间件是一回事吗？

**套路 B：设计选择 → 为什么不那样**

> **答**：……收到数据后**先塞进一个阻塞队列**就返回……
> **追问**：为什么不直接在回调里算，非要加个队列？

**套路 C：数字/现象 → 那会怎么样**

> **答**：……队列满了就**丢最旧的那一帧**……
> **追问**：那不就保证不了每帧必达了？

### 对照

❌ **孤立的追问**（前后没有因果）：
> **答**：我用工厂模式管理检测器。
> **追问**：你了解虚函数表吗？

✅ **长出来的追问**：
> **答**：我用**抽象基类 + 工厂**统一管理，主循环只认基类。
> **追问**：那"同一个调用、不同实现"具体是怎么做到的？

---

### 特例：总览题要做成「追问链 + 导航」★★（2026-10-15 用户明确要求）

**什么样的题算总览题**：每个技术点的第 1 题（"整体怎么设计的" / "这个模块是干嘛的"），以及开场自述题。
特征是**一句话里连着抛出 5~8 个名词**——插件、队列、工作线程、周期……

用户的原话逻辑：

> "我回答啥，人家肯定会根据我回答的提问呀。然后再看简历上的条目。"

所以总览题**不受"每题只留一条主追问"的限制**。你抛一个词，他就咬一个词，你必须提前把这条链铺好，否则临场断片。

**写法四步**

1. **按答案里词出现的顺序编号追问**（`**追问 1**：` … `**追问 N**：`），一个词一个，**别跳序**——顺序就是真实面试里被问的顺序。
2. **每个追问只给 2~3 句短答**，目的是**顶住这一轮**，不是讲透。
3. **讲透交给后面的独立题**：短答里不展开，靠末尾的导航块指过去（避免和后面的题重复一大段）。
4. **末尾必须加 `📍` 导航块**——把简历原话里每一个技术词，对上具体题号。

数量控制在 **6~10 个**；超过 10 个说明答案本身该拆题了。

**示例（条目四 Q1-1，一句话抛出 8 个词）**

| 答案里抛出的词 | 追问 |
|---|---|
| 算法插件 | 插件是什么意思？跟宿主程序怎么配合？ |
| 结构化目标流 | 到底是什么？是图像吗？ |
| 订阅收下 | 怎么订阅的？收到的是原始数据还是解析好的？ |
| 阻塞队列 | 是你自己写的吗？怎么实现的？ |
| 阻塞 | 为什么非要"阻塞"？队列空的时候线程在干嘛？ |
| 一个工作线程 | 为什么只有一个？不怕算不过来吗？ |
| 一组检测器 | 一组是多少个？它们之间什么关系？ |
| 到配置的周期…出数 | 周期怎么定的？算出来的数给谁了？ |

末尾两块（缺一不可）：

````markdown
> 📍 **这条流水线一定会被拆开问**——简历第 4 条里每个词，对应后面哪一题：
> - **"DDS 订阅" / "独立工作线程消费"** → 技术点 2 的 Q2-1、Q2-4
> - **"有界阻塞队列"** → Q2-2（隔开的好处）、Q2-3（满了会丢）
> - **"生产者-消费者模型" / "数据接收与检测计算解耦"** → Q2-1 追问、Q2-4
> - **"抽象基类 + 工厂模式"** → Q1-2、Q1-3
> - **"逐帧累积、到点结算"** → Q1-5
>
> 背法：Q1-1 是**目录**，后面 22 题是**展开**。答完别停，等他挑词。
````

**为什么导航块是强制的**：简历上写的每一个术语都一定会被问到。导航块是"简历原话 → 题号"的**倒查表**，保证你说的每个词都有落点，不会被追问到空处；同时它也是背 Q1-1 时的路线图。

## 7. 每个条目开头必须写两块

````markdown
## 条目 X：<名字>

> **简历原话**
> （逐字引用简历上那一句，一个字都不要改，这是所有题的口径基准）

> 🔴 **本条 N 条专属红线（背题前先看）**
> 1. （不能说的话 / 不能承认的功能 / 不是自己做的部分）
> 2. （尺度：全程说"参与"）

> **本条 N 个技术点**：① A（x 题） ② B（y 题）
````

**为什么**：所有题都是"简历原话"的展开，脱离原话就会讲偏、讲漏、讲过头。

## 8. 组织方式（三层）

```
简历条目（如「交通参数检测服务」）
  └── 技术点（如「检测器框架与多态」）
        └── 问题（5~10 题，由浅入深）
```

**标记规范**

| 标记 | 含义 |
|---|---|
| `[必背]` | 必须一字不差背下来 |
| `[加分]` | 被追问时能说上来就加分 |
| `[保底]` | 答不上来时用来划边界的诚实话 |
| `★` / `★★` | 出现频率，★★ = 大概率被问 |

## 9. 写完自检清单

- [ ] 答案**能一口气念完**吗？读一遍计时，超过 30 秒就再砍
- [ ] 有没有**函数名 / 宏名 / 字段名 / 路径**出现在答案里？（只许在 📌 里）
- [ ] 技术点内题序是**由浅入深**的吗？
- [ ] 追问的主语**来自上一句答案**吗？不是另起一个话题吧？
- [ ] **总览题**做成编号追问链了吗？末尾有 `📍` 简历术语导航块吗？（见 §6 特例）
- [ ] 追问链的短答是"**顶住这一轮**"（2~3 句），没有展开成长答案吧？
- [ ] 全程说「**参与**」，没说"我从零设计"吧？
- [ ] 该条目的**专属红线**写在条目开头了吗？
- [ ] 每条 `**答**` 后面有**独立的段落**，不是贴着标题写吧？
- [ ] 改完复核过文件（行数 / 题目数 / 有没有断行错位）吗？
- [ ] 用 Python 脚本改过 md 的话，**换行还是纯 CRLF** 吗？（见 §12 工具坑）

## 10. 反模式（明确禁止）

| 禁止 | 原因 |
|---|---|
| 答案写成要点罗列 / 汇报体 | 面试念不出口 |
| 一句一行、铺满半页 | 太长，背不下来 |
| 满篇函数名、结构体、字段名 | 面试官看不到代码，且违反红线 |
| 追问跟上一句答案无关 | 用户明确要求必须有因果关联 |
| 把没做过的部分写成"我做的" | 一追问就穿帮 |
| 说"我从零设计了这套系统" | 简历基调是"参与" |
| 普通题挂三四个追问 | 背的时候没有主线（**总览题例外**，见 §6 特例） |
| 总览题只给一条追问 | 面试官会从你抛的每个词往下咬，临场必断片 |
| 总览题末尾没有 `📍` 导航块 | 简历术语没有落点，被追问到空处 |
| 为了凑数编造实现细节 | 违反事实红线 |

## 12. 工具坑：Python 脚本改 md 会偷偷换掉换行符（2026-10-15 踩过）

`0面试QA总表.md` 是**纯 CRLF**。用 Python 脚本改它时若写：

```python
io.open(P, "w", encoding="utf-8", newline="\n").write(text)
```

会把**整个文件从 CRLF 改成 LF** —— git 里变成全文件 diff，Windows 记事本打开也可能异常。

**做法**：

1. **优先用 Edit 工具改**，别脚本化；
2. 必须脚本化时，改完**立刻把 LF 统一转回 CRLF**：
   ```python
   s = io.open(P, encoding="utf-8").read()
   s = s.replace("\r\n", "\n").replace("\r", "\n").replace("\n", "\r\n")
   io.open(P, "wb").write(s.encode("utf-8"))
   ```
3. 改完核对：`CRLF 数 == 行数`，裸 LF 数为 0（PDF 构建脚本每次会打印 `CRLF:`，可直接看）。

## 13. 简历改版后怎么同步 QA（2026-10-14 / 10-15 实战）

简历措辞一改，**必须回头扫整份 QA**，只改条目开头那个「简历原话」块是不够的。

**五步**

1. **逐字替换**条目开头的「简历原话」块——一个字都不要润色。
2. **全文搜旧措辞残留**：grep 旧句里的特有短语（不只题目里的引用，正文口播里也常带），确保 **0 命中**。
3. **查新术语有没有落点**：新写进简历的每个技术词，后面必须有题覆盖；没有就补题，或至少补进 `📌`。
4. ★ **查自相矛盾（最容易漏的一步）**：新说法如果和已有答案冲突，**必须重写旧答案**，不能两边都留着——面试官会拿着你的简历逐句对。
   - 实例：新简历第 5 条写"质量门控…**支撑流量与车头时距统计**"，但 Q3-5 原写"我简历上写的是车流量，所以这道门实际上没拦我统计的车" → 直接打架。改法不是删哪一句，而是**把口径写准**："门控护的是这两份统计里行人 + 非机动车那部分口径（流量出的是分车型明细，行人和非机动车就在里面），机动车总流量那一栏不受影响。"
5. **重出 PDF**：`python C:\Users\sunboxue\WorkBuddy\airos智路\.workbuddy\pdfbuild\build.py`
   （校验脚本 `validate.py` 要用托管 venv：`C:\Users\sunboxue\.workbuddy\binaries\python\envs\default\Scripts\python.exe`，系统 Python 没装 pymupdf。）

## 14. 精简版（考前突击版）怎么来（2026-10-15 建）

用户明确要过一份「**看不过来时用的短文版**」，产出 `0面试QA-精简版.md`（35 题 / 25 页 PDF），**不替代原表**。

### 铁律

> **精简版【逐字照搬】原表答案，绝不重写。**
> 两份文档一旦说法不一致，用户背的时候就分裂了——精简版只做三件事：**删次要题 / 压条目红线 / 给总览题补追问链**。

### 做法：脚本抽取，不手抄

`python C:\Users\sunboxue\WorkBuddy\airos智路\.workbuddy\build_lite.py`

- 按题目标题的**唯一子串**从原表切块（块 = 该行到下一个边界行之前），匹配数 ≠ 1 就报错退出；
- `PLAN` 列表决定顺序与取舍；`("qs", ...)` 表示**删掉该块原有的追问**（已并入重排的追问链）；
- 块尾的 `**✅ 一句话版本**` / `📌 自己复习` 自动识别为 tail，**排在追问链之后**；
- **题 + 链接 + tail 合成一个整体**，中间不插 `---`（插了会把答和链割裂）；
- 输出 **CRLF**。

### 选什么题

`[必背]` + `★★` 高频 + **诚实题**（容易穿帮的）+ 每个条目的**总览题**。
砍掉**同类重复题**和**纯加分储备题**——不是不考，是优先级低。本次 129 → 35 题。

### 精简版里追问链给谁做

只给**条目级总览题**：开场 Q0.1 + 每个条目的第 1 题。技术点内部的第一题仍只留 1 条主追问。
条目级总览题的链要带**跨条目导航**（`👉 深挖见条目 X Qx-x`），让开场题成为整张地图。

### 改了原表之后

**重跑 `build_lite.py` 即可重建**——题号是通的，PLAN 不用改（除非要换选题）。

## 15. 语言的"专业度"到底放多少（2026-10-16 四版迭代定稿）

用户嫌答案"太难懂"，来回否了三版，第四版才过。**判据只有一条**：

> ⭐ **这个词在代码里看得见吗？**
> **看得见 → 可以说**（map / key-value / if-else / switch / `#define` / `constexpr` / new / class / 对象 /
> 头文件 / include / 指针 / 虚函数 / 继承 / 线程 / 锁 / .cpp / .so / O(log n) / `clear()` / `join()`）
> **看不见 → 挪到 `📌 自己复习`**（开闭原则 / 依赖倒置 / 控制反转 / 编译期·运行期 / 解耦 / 藏在…后面 / 单一职责）

**四版过程（别重走）**

| 版本 | 样子 | 用户反馈 |
|---|---|---|
| v1 | 纯大白话，一个术语没有 | ❌ "太白话了" |
| v2 | 塞 13 个设计模式术语 | ❌ "太复杂了" |
| v3 | 只留 3 个设计模式术语 | ❌ "还是复杂" |
| **v4** | **大白话骨架 + 简单具体工程词** | ✅ 通过 |

**v4 长什么样（条目一 Q2-1 定稿片段）**

```
好处就一句话：**加一款新相机，框架不用动**。
不用工厂的话，框架里得写一串 **if-else**…
用了工厂，框架手里只有一张 **map**：**key** 是配置里写的设备名，**value** 是"这个对象怎么造"…
每个驱动文件末尾写一行**宏**（`#define` 那套）…
```

**一句话记：写给人听的是"这段代码在干什么"，专业名词只留那些"写代码时手会敲到的词"。**

## 16. 「八股补给」块怎么加（2026-10-16 新增格式）

每个问题在 **`追问` 之后、`📌 自己复习` 之前**插一个块，用来放"面试官顺着往下挖的底层知识"，供用户**自学**，不进嘴。

**格式**

```markdown
**八股补给**：

**Q1：八股问题？**

> 3~5 句口语答案，同样遵循"代码里看得见的词才说"。
> 每份 3~5 个 Q，挑**跟这一题直接相关**的，不要凑数。
```

**选题原则**

1. **必须从这一题的答案里长出来**——是"你刚才那句话，我再往下问一层"。
2. **同一份文档里不要重复讲同一点**（例：`ldd` / `dlerror` 归 Q3-2，`接口扩展代价` 归 Q1-7，别两边都写）。
3. **优先选 C++ 岗真会考的**：进程 vs 线程、TCP vs UDP、死锁四条件、虚表、智能指针、map vs unordered_map、
   条件变量为什么要配 while、const vs constexpr vs `#define`、序列化为什么不能直接发结构体、ABI vs API。
4. **答案同样是口语**，能念出口；真要报函数名/选项名（`-g` / `-fPIC` / `unordered_map`）就报，这些属于"看得见的词"。
5. **涉及红线的（比如"上报不是我做的"），八股只讲通用知识，不要写成"我们项目里用了 X"。**

**当前落地**：`0面试QA总表.md` 精简版那 35 题**每题一个八股补给块**；
`grep -c "八股补给" 0面试QA-精简版.md` 应等于 **35**。
