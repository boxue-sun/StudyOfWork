# 面试 QA 写作规范

你面对的是一位**正在准备 C++ 开发岗面试的实习生**。他要的不是"技术文档"，而是**"面试官一问，我能张嘴念出来"**的稿子。

---

## 0. 和「面试笔记助手」的分工

| skill | 管什么 |
|---|---|
| 面试笔记助手 | **啃代码、讲项目、配 SVG 流程图**，产出学习笔记 md |
| 本规范 | **把项目经验写成面试题**，产出 / 维护 `0面试QA总表.md` |

**顺序：先啃代码 → 再写 QA。** QA 里每一句说法都要能在代码里找到依据（文件:行号），找不到就明说，绝不编。

---

## 1. 用户画像（决定你怎么写）

| 维度 | 事实 | 对你的要求 |
|---|---|---|
| 身份 | 实习生 | 全程说「**参与**」，绝不说"我从零设计" |
| 基础 | C++ 基础一般 | **大白话 + 类比**，别堆术语 |
| 状态 | 容易焦虑："内容太多记不住" | 主动做**减法**：区分"必背 / 储备 / 知道有这回事" |
| 习惯 | 常用 "ok" 表示收到 | 不必追问，直接执行下一步 |
| 偏好 | 喜欢用图理解结构 | 结构/层次关系配 SVG |

---

## 2. 三条硬标准（用户的原话，最重要）

1. **答案要更好理解、更好背、字数少一点**
2. **问题要从简单到深入**
3. **追问要有关联**——"面试官是听到你的回答里有疑惑才追问的，比如你提到用这个技术实现了什么，他就问这个技术是啥讲一下"

写任何一道题之前，先拿这三条卡一遍。

---

## 3. 每题的标准格式

````markdown
#### Qx-x 口语问题 [标记]

**答**：

（3~5 句，一段念完）

**追问**：从答里那个加粗的词接着问
> （2~3 句）

📌 *自己复习（面试别说）：函数名 / 字段名 / 路径*
````

细则：

- **问题用面试官的真实口吻**：他看不到代码，只会问「你怎么设计的 / 为什么 / 踩过什么坑 / 换你会怎么改」。
- **答案必须能张嘴念**：是口语段落，不是要点罗列；不要写成"第一 第二 第三"的汇报体。
- **函数名、宏名、字段名、文件路径一律不进嘴**，全部挪到 `📌 自己复习`。
- **每题只留一条主追问**，不要堆三条；追问链靠跨题衔接来延伸。
- 需要提醒口径的地方，用 `> ❗ **误区：……**`、`> 💡`、`> 🔴` 三种标记，紧跟在对应答案之后。

---

## 4. 答案怎么写（重点：好背）

**硬指标**

| 项 | 要求 |
|---|---|
| 长度 | **3~5 句，约 120~180 字** |
| 念完 | **不超过 30 秒** |
| 结构 | 第 1 句给结论，后面补理由 / 例子 / 类比 |
| 分段 | 3~5 句合成**一个段落**，不要一句一行 |

**怎么做减法**

- 删掉铺垫句（"这个问题其实很复杂""首先要说明"）；
- 删掉和上一题重复的说明；
- 一个意思只说一次；
- 保留**结论 + 一个理由 + 一个类比**，其余砍掉。

**加粗的用法（很关键）**

- 只给两类东西加粗：**技术关键词** 和 **下一题要追问的钩子**；
- 不要整段加粗，否则背的时候没有重点。

**❌ 原来的写法（太长、书面、绕）**

> 如果直接在框架里写判断——是这个牌子就创建这个类的对象，是那个牌子就创建那个类的对象——那每来一个新厂商，我就要打开框架代码改一遍、再把整个框架重新编译一遍。框架是所有人共用的基础件，张三接入改一次、李四接入改一次，风险和协调成本都很高。还有一个更隐蔽的问题：这么写之后框架就依赖了所有具体驱动，随便哪个驱动改个头文件，框架都得重编。工厂模式把"选哪个设备"这个决策，从编译期推迟到了运行期，从代码里搬到了配置文件里。

**✅ 现在的写法（三句，念完 20 秒）**

> 不行，因为那会让主循环跟每一类检测器**绑死**。如果写 if-else，加一类检测器就要打开主循环改一遍，改八类主循环就膨胀成一团，谁都不敢动。用抽象基类之后，所有检测器在**主循环眼里长得一样**——都是"喂一帧进去、让它出一次数"这两个动作，所以主循环能一个 for 循环统一调度。

## 5. 问题怎么排序（由浅入深）

每个技术点内统一走这**五阶段**：

```
① 是什么（这模块干嘛 / 整体怎么设计的）
② 怎么做 / 为什么这么做
③ 细节和容易答错的点
④ 底层原理（八股：虚函数表、锁、容器…）
⑤ 有什么不足 / 换你会怎么改
```

**示例（条目四技术点 1）**

| 序 | 阶段 | 题 |
|---|---|---|
| Q1-1 | ① 是什么 | 检测服务整体上怎么设计 |
| Q1-2 | ② 为什么 | 为什么用抽象基类 + 工厂，if-else 不行吗 |
| Q1-3 | ② 怎么做 | 工厂具体怎么造出检测器 |
| Q1-4 | ② 设计 | 基类接口为什么只有两个 |
| Q1-5 | ③ 细节 | 「逐帧累积、到点结算」是什么意思 |
| Q1-6 | ③ 易错 | 一共几类检测器（诚实口径题） |
| Q1-7 | ③ 细节 | 车道级和断面级怎么分开 |
| Q1-8 | ⑤ 改进 | 有什么不足 / 怎么改 |

**跨技术点也要由浅入深**：先"框架整体"，再"数据怎么流进来"，最后"最底层的判定算法"。

## 6. 追问怎么设计（★★ 用户最看重这一条）

### 唯一规则

> **追问的主语，必须是上一句答案里刚刚出现的那个词。**

面试官看不到你的代码，他只能从你的回答里抓"没听懂的词"来追。所以：

- 答案里提到**某个技术** → 追问就问"这个技术是什么、讲一下"；
- 答案里做了**某个选择** → 追问就问"为什么不用另一种"；
- 答案里给了**一个数字 / 现象** → 追问就问"那会怎么样 / 怎么定位"。

### 三种标准套路

**套路 A：技术名词 → 讲一下**

> **答**：……上游感知结果通过 **Fast-DDS** 推给我……
> **追问**：Fast-DDS 是什么？跟你们另一套中间件是一回事吗？

**套路 B：设计选择 → 为什么不那样**

> **答**：……收到数据后**先塞进一个阻塞队列**就返回……
> **追问**：为什么不直接在回调里算，非要加个队列？

**套路 C：数字/现象 → 那会怎么样**

> **答**：……队列满了就**丢最旧的那一帧**……
> **追问**：那不就保证不了每帧必达了？

### 对照

❌ **孤立的追问**（前后没有因果）：
> **答**：我用工厂模式管理检测器。
> **追问**：你了解虚函数表吗？

✅ **长出来的追问**：
> **答**：我用**抽象基类 + 工厂**统一管理，主循环只认基类。
> **追问**：那"同一个调用、不同实现"具体是怎么做到的？

## 7. 每个条目开头必须写两块

````markdown
## 条目 X：<名字>

> **简历原话**
> （逐字引用简历上那一句，一个字都不要改，这是所有题的口径基准）

> 🔴 **本条 N 条专属红线（背题前先看）**
> 1. （不能说的话 / 不能承认的功能 / 不是自己做的部分）
> 2. （尺度：全程说"参与"）

> **本条 N 个技术点**：① A（x 题） ② B（y 题）
````

**为什么**：所有题都是"简历原话"的展开，脱离原话就会讲偏、讲漏、讲过头。

---

## 8. 组织方式（三层）

```
简历条目（如「交通参数检测服务」）
  └── 技术点（如「检测器框架与多态」）
        └── 问题（5~10 题，由浅入深）
```

**标记规范**

| 标记 | 含义 |
|---|---|
| `[必背]` | 必须一字不差背下来 |
| `[加分]` | 被追问时能说上来就加分 |
| `[保底]` | 答不上来时用来划边界的诚实话 |
| `★` / `★★` | 出现频率，★★ = 大概率被问 |

---

## 9. 写完自检清单

- [ ] 答案**能一口气念完**吗？读一遍计时，超过 30 秒就再砍
- [ ] 有没有**函数名 / 宏名 / 字段名 / 路径**出现在答案里？（只许在 📌 里）
- [ ] 技术点内题序是**由浅入深**的吗？
- [ ] 追问的主语**来自上一句答案**吗？不是另起一个话题吧？
- [ ] 全程说「**参与**」，没说"我从零设计"吧？
- [ ] 该条目的**专属红线**写在条目开头了吗？
- [ ] 每条 `**答**` 后面有**独立的段落**，不是贴着标题写吧？
- [ ] 改完复核过文件（行数 / 题目数 / 有没有断行错位）吗？

---

## 10. 反模式（明确禁止）

| 禁止 | 原因 |
|---|---|
| 答案写成要点罗列 / 汇报体 | 面试念不出口 |
| 一句一行、铺满半页 | 太长，背不下来 |
| 满篇函数名、结构体、字段名 | 面试官看不到代码，且违反红线 |
| 追问跟上一句答案无关 | 用户明确要求必须有因果关联 |
| 把没做过的部分写成"我做的" | 一追问就穿帮 |
| 说"我从零设计了这套系统" | 简历基调是"参与" |
| 一题挂三四个追问 | 背的时候没有主线 |
| 为了凑数编造实现细节 | 违反事实红线 |

---

## 11. 最小可复用模板（新建技术点时直接抄）

````markdown
### 技术点 N：<名字>（N 题）

---

#### QN-1 <是什么/整体上怎么做的>？[必背]

**答**：
（结论句。）（理由句。）（类比 / 例子句。）

**追问**：（从答里的钩子句接着问）？
> （2~3 句）

---

#### QN-2 为什么<这么做>，<另一种方案>不行吗？[必背] ★

#### QN-3 <具体怎么做 / 细节>？[加分]

#### QN-4 <容易答错的点>？[加分] ★★ 容易答错

#### QN-x 这套设计有什么不足？重做你会怎么改？[加分] ★ 收尾必问
````
