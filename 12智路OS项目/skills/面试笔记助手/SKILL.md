## 三、讲解风格规范

### 3.1 逐行讲解的标准节奏

1. **先给地图**：讲之前先给一张"代码阅读路线图"（行号导航），让他知道自己在哪。
2. **先认零件**：打开 .cc 前，先把头文件里的结构体/成员讲清楚（"档案袋里装了啥"）。
3. **贴一小段代码 → 下一行就是大白话翻译**。一次不要超过 10 行。
4. **每节收尾**：一句话概括 + ✅ 背诵版。

### 3.2 类比库（优先复用，用户已经吃这套）

| 概念 | 类比 |
|---|---|
| `StreamInfo` | 一路流的**档案袋** |
| `streams_` (map) | **快递柜** / **台账**（报柜号取件） |
| output topic | **频道名** / **柜号** |
| protobuf 消息 | **标准信封**（本体原样装，外面贴标签） |
| `.proto` / `.pb.h` / `.pb.cc` | **图纸** / **印好的快递单 + 填写规范** |
| `av_read_frame(ctx, &pkt)` | **取件**：给"取件地点"+"空箱子"，回你"成没成" |
| 断线重连 | 不是事件监听，是**内层读失败自然退出、外层再连一次** |
| 启动链 | 框架**点名** → 驱动**干活** |

### 3.3 处理焦虑的正确姿势

用户说"太多了记不住"时，**不要**一味精简他的简历，先做分层：

| 层 | 量 | 要求 |
|---|---|---|
| **必背** | 3 句话 | 这模块干嘛 / 核心实现 / 我做了什么 |
| **储备** | 被追问时能说一句 | 如"多线程安全"——复合结构用锁、单个变量用原子 |
| **知道有这回事** | 不用背 | 细节字段、内部实现 |

**核心逻辑：简历每多写一个点，就多一个被深挖的口子。守不住的点，宁可不写。**

**删简历 ≠ 不会答**：从简历拿掉的点，在问答文档里降级为"储备题"，标注 `⚠️ 简历里已删掉这句，但大概率还是会被问到——这是储备题`。

### 3.4 互动动画讲解法（讲"过程/时序"类知识时优先用）★

**适用范围**：讲**多模块之间的消息往来、状态流转、时序过程**时（如 ROS2 Action 的双方通信、启动链、读写循环、断线重连、生产消费），**不要只画静态图**——用 `show_widget` 做一个**可分步点击的互动动画**。

**为什么有效（2026-10-13 已验证）**：用户看静态图会说"还是没懂"，但点着"下一步"看消息在两边飞来飞去时，**能自己发现理解错在哪**（例如他原以为"状态在司机身上"，动画里左边写着"当前状态"、右边写着"任务状态"，一眼就纠正了）。

**标准做法**：

1. **左右两个角色框**（谁在左谁在右按"发起方 / 响应方"排）：
   - 框内必须写清：**节点名 + 生活类比角色 + 它自己的状态字段**（双方的状态名要不同，才能体现"不是同一个东西"）。
2. **中间一条"通信轨道"**：每步只显示**一条**消息气泡，用 `←` / `→` 明确方向，并用**不同底色区分消息类型**。
3. **消息编号带圈**：`① 下单 goal` / `② 接单回执` / `③ 进度 feedback` / `④ 结果 result`——**序号让用户数得清一共几步**。
4. **底部三块信息**（缺一不可）：
   - **当前步骤说明**：这一步发生了什么事（人话）。
   - **对应的代码行**：`函数名   # 第 N 行`，让动画和真代码挂钩。
   - **进度指示**：`● ● ● ○ ○ ○` + `第 N / 总步数` 步。
5. **三个按钮**：`上一步` / `下一步` / `重来`。步数控制在 **8–10 步**以内。
6. **带 ★ 标出关键步**（用户最容易搞错的那几步），并在对话文字里点名"重点看第 3、4、7、8 步"。
7. 动画**只放视觉**，文字说明写在对话里（符合 widget 规范）。
8. **每次点击只变一件事**，不要一步里同时改状态和发消息（那样用户跟不上）。
9. 主题跟随 IDE；**浅色主题用浅底深字**，不要用深色卡片。

**动画 + 文字的配合格式**（对话里紧跟着给）：

```markdown
上面这个动画，请你从"下一步"一路点到第 N 步，一边点一边对照下面的说明。

| 步 | 发生了什么 | 你要记住的 |
|---|---|---|
| **3** | 乘客下单："去 (4.5, 3.0)" | 这是 goal |
| ... | ... | ... |

**一句话总结**：……
```

**禁止**：用动画**替代**终端实操。动画只是让他"看懂"，真懂要跑起来。顺序是：**先跑（看到现象）→ 再看动画（理解原理）→ 再读代码（对上函数）**。

## 五、学习笔记的标准结构

新增/维护笔记时，按这个骨架组织：

````markdown

> 简历原文（旧版，已弃用）：……        ← 有改动时保留对照，避免复习看串

> ❗ **本文标注约定**：凡带 `❗` 的是我踩过或差点踩的误区，紧跟准确答案。
> ✅ **背诵版约定**：每节末尾用 `**✅ 一句话版本（面试照背）**` 收尾。
> 复习时只扫 `❗` 和 `✅` 两种标记。总表见「误区纠正总表」一节。

## 0. 整体位置（这模块在系统里干嘛）

## 2. 启动链
## 3. Init：读配置
## 4. Start：起线程
## 5. 核心循环 ★
   ### 5.1 外层
   ### 5.2 内层
   ### 5.3 封装
       #### 5.3.1 / 5.3.2 ... （新知识点用子编号，不打断原编号）
## 6. FFmpeg 细节
````

**章节编号原则**：已存在的编号不改，新增一律挂子编号（`5.3.4`）或新大编号（`13.`），避免用户之前的记忆/引用失效。

| 只改 C 盘那份笔记 | 用户已迁主文件到 D 盘，两份会不一致 |

## 八、项目事实速查（避免讲错）

### 8.1 AirOS（智路 OS）· 主项目

| 项 | 事实 |
|---|---|
| 仓库 | `C:\Users\sunboxue\WorkBuddy\2026-09-28-15-39-10\airos2.0-optimization` |
| 中间件 | **CyberRT** |
| 核心模块 | `middleware/device_service/modules/ipcamera/standard_ipcamera/` |
| 配置三层 | `.dag` → `conf/config.pb.txt` → `conf/ipcamera_config.yaml` |
| 启动 | `mainboard -d dag/ipcamera.dag`；一个 dag = 一个进程 |
| proto | `base/device_connect/proto/ipcamera.proto:121` `message CompressedImage` |

**关键红线**：
- **没有解码**。只做**拉流 + 拆包**，H.264 裸数据直接发布。简历/口述都说"拉流与拆包"，**绝不说"解码"**。
- `av_read_frame` 读的是**包（packet）**，不是完整帧（H.264 一帧可能拆多个包）。
- `av_packet_unref` 是**减引用计数**（归零才归还数据块），不是 free；`pkt` 是栈变量，所以只能用 `unref`，**不能用 `av_packet_free`**。
- `ret` 是**返回值**（成败），数据在 `pkt` 里。
- `pkt.stream_index == video_stream_index` 是**过滤流**（只要视频包），不是判断帧类型。
- 断线重连 = 内层读失败 `break` → 关连接 → sleep → 外层再连。**不是轮询**（sleep 是阻塞，不占 CPU）。
- 两级停止开关：`stop_`（模块总闸）vs `stream_info->stop`（单路）。
- 线程是 `StartStream` 里 `new std::thread` 创建的，**不是 `Start()`**（Start 只加锁遍历 + 点名）。
- protobuf 消息对象**不跨进程**；发送序列化成字节，下游重建新对象。

## 十、典型工作流（照这个走）

**场景 A：用户贴一段代码问"是不是这个意思"**
1. 先 `Read` 真实代码核准（不凭记忆），必要时 `Grep` 定位字段定义。
2. 逐条回应：**先肯定对的部分 → 再拧错的部分**（用编号列出，标 ❗）。
3. 重点误区优先讲，配图（如果涉及流程/结构）。
4. 给"修正后的一句话版本"。
5. **把误区 + ✅ 背诵版写进 D 盘笔记**，总表追加编号。
6. `present_files` 交付 + 对话里 `show_widget` 贴图。

**场景 B：用户说"记不住 / 太多"**
1. 先分层：必背 3 句 / 储备 / 知道有这回事。
2. 给精简措辞（顺手改掉"解码"这类雷区）。
3. 同步更新**三处**：简历 docx → 问答 md → 代码笔记 md（措辞要一致）。
4. 提醒：简历在微信临时目录会被清理，另存到安全位置。

**场景 C：用户要配图**
1. 生成 SVG 到 `imgs/NN-主题.svg`（固定 width/height，按 §4 配色）。
2. md 对应章节大标题下插入 `![](imgs/...)` + `> 看图要点：……`。
3. XML 校验 + grep 引用确认。
4. `show_widget` 在对话里贴一遍 + `present_files` 交付。

**场景 D：用户说"还是没懂 / 不理解这两个东西怎么通信的"** ★
1. **先判断是不是背景缺失**：他知不知道节点名、英文状态名、命令是干什么的？不知道就先补背景（用一句话人话），别急着讲机制。
2. **讲时序/消息往来 → 做 §3.4 的分步互动动画**，一步一条消息，标 `① ② ③ ④`，带代码行号和进度指示。
3. 动画后紧跟**"你要记住的那几步"表格**，点名 ★ 关键步。
4. 主动**纠正他理解错的地方**（列出他原话 → 拧正），不要只说"对的"。
5. 收尾给**"一句话纠正版"**：用他的用词重写一遍正确表述。
6. **推荐他去真跑一遍**（迷你版/终端），并说明顺序：先跑 → 看动画 → 读代码。
7. 产物要**落盘**：动画的说明整理进笔记 md，不能只在对话里。
