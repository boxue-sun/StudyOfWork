
# 回调函数笔记

## 1. 一句话理解

回调函数就是：**把函数当作参数传给别的对象/函数，别人在合适的时机替你调用它。**

不是你去主动调用，而是你提前把“要做什么”告诉对方，对方在事件发生时回头调用你。

---

## 2. 核心：注册 vs 调用

| 阶段                   | 做什么               | 回调执行了吗 |
| ---------------------- | -------------------- | ------------ |
| 构造时传入回调         | 把回调保存到成员变量 | 没有         |
| 事件发生 / 调用 onData | 执行`cb_(x)`       | 执行了       |

```cpp
Device d([](int x) {
    std::cout << "收到数据: " << x << std::endl;
});   // 只是保存回调，不执行

d.onData(42);  // 这里才真正调用回调
```

> 构造时是“登记/注册”，事件发生时才是“调用”。

---

## 3. 基本代码模型

```cpp
using Callback = std::function<void(int)>;

class Device {
    Callback cb_;
public:
    Device(Callback cb) : cb_(cb) {}  // 保存回调

    void onData(int x) {
        if (cb_) cb_(x);              // 触发回调
    }
};

int main() {
    Device d([](int x) {
        std::cout << "收到数据: " << x << std::endl;
    });

    d.onData(42);  // 输出：收到数据: 42
}
```

对应关系：

| 代码                                           | 含义                             |
| ---------------------------------------------- | -------------------------------- |
| `using Callback = std::function<void(int)>;` | 定义回调类型：接收 int，无返回值 |
| `Callback cb_;`                              | 成员变量，用来存回调             |
| `Device(Callback cb) : cb_(cb) {}`           | 构造时保存回调                   |
| `if (cb_) cb_(x);`                           | 回调存在就调用它                 |
| `Device d([](int x){...});`                  | 传入 Lambda 作为回调             |
| `d.onData(42);`                              | 触发回调                         |

---

## 4. 回调如何解耦

不用回调：

```cpp
void Device::onData(int x) {
    std::cout << "收到数据: " << x << std::endl;  // 写死了
}
```

问题：`Device` 和具体处理逻辑绑死，想换功能就得改 `Device` 源码。

用回调：

```cpp
void onData(int x) {
    if (cb_) cb_(x);  // 只负责调用，不关心做什么
}
```

`Device` 只知道：

- 有一个回调 `cb_`
- 形状是 `void(int)`
- 数据来了就调用它

具体是打印、保存、推流还是 AI 识别，`Device` 完全不知道。

**解耦本质：把“谁触发”和“做什么”分开。**

| 角色       | 负责         |
| ---------- | ------------ |
| `Device` | 什么时候触发 |
| 回调函数   | 触发时做什么 |
| 外部使用者 | 决定具体功能 |

---

## 5. 一个回调接口，多种功能

同一个 `Device` 类，不用改代码，传不同 Lambda 就有不同行为：

```cpp
Device d1([](int x) {
    std::cout << "打印: " << x << std::endl;
});

Device d2([](int x) {
    saveToFile(x);   // 保存
});

Device d3([](int x) {
    aiProcess(x);    // AI 处理
});
```

准确说法：

> 不是同一个函数体有多个功能，
> 而是同一个回调接口可以接受多种实现，表现出多种功能。

---

## 6. 一个事件，多个回调

用 `vector<Callback>` 保存多个回调，事件发生时依次调用。

```cpp
class Device {
    std::vector<Callback> cbs_;
public:
    void addCallback(Callback cb) {
        cbs_.push_back(cb);
    }

    void onData(int x) {
        for (auto &cb : cbs_) {
            if (cb) cb(x);
        }
    }
};
```

使用：

```cpp
Device d;

d.addCallback([](int x) {
    std::cout << "打印: " << x << std::endl;
});

d.addCallback([](int x) {
    saveToFile(x);
});

d.addCallback([](int x) {
    aiProcess(x);
});

d.onData(42);  // 三个功能都会执行
```

这是观察者模式 / 发布订阅的雏形。

---

## 7. “函数可以不被定义”的准确理解

C++ 中函数最终要被调用，肯定得有定义。
回调允许：**调用者不定义具体实现，只规定接口/类型。**

```cpp
using Callback = std::function<void(int)>;
```

只是规定：

> 回调必须长成 `void(int)` 的样子。

具体函数体由外部传入：

```cpp
Device d([](int x) {
    std::cout << x << std::endl;
});
```

`Device` 作者不知道你会传什么函数，只知道你会给一个 `void(int)` 的可调用对象。

纯虚函数同理：

```cpp
virtual bool Init(const std::string &config_file) = 0;
virtual void Start() = 0;
```

基类只声明接口，具体实现由子类写。

> 调用者只规定“长什么样”和“什么时候调用”，具体“怎么做”由外部/子类提供。

## 8. 普通函数直接写 vs 回调

| 方式           | 谁调用                               | 什么时候调用   | 灵活性     |
| -------------- | ------------------------------------ | -------------- | ---------- |
| 直接写普通函数 | 你自己主动调                         | 写代码时决定   | 低，写死   |
| 回调           | 别人（库/框架/Device）在事件发生时调 | 运行时事件决定 | 高，可替换 |

普通函数也可以当回调：

```cpp
void myHandler(int x) {
    std::cout << "收到数据: " << x << std::endl;
}

int main() {
    Device d(myHandler);  // 普通函数也能当回调
    d.onData(42);
}
```

区别不在于函数是不是普通函数，而在于：

> 你是直接写死调用它，还是把它作为参数交给别人，由别人在合适时机调用。

---

## 9. 回调 vs 虚函数

| 方式   | 实现放在哪                      | 灵活性                     |
| ------ | ------------------------------- | -------------------------- |
| 虚函数 | 子类里，和对象绑定              | 运行时多态，但继承关系固定 |
| 回调   | 外部传入，可以是任意函数/Lambda | 更动态，随时可换           |

两者都能解耦，但回调更轻，不需要为了一个行为专门继承一个类。

---

## 10. 回调的优点

1. **解耦**：事件源不依赖具体业务逻辑。
2. **灵活**：运行时可以换回调，不用改事件源代码。
3. **可复用**：同一个 `Device` 类能用于打印、保存、推流、AI。
4. **一对多**：一个事件可以通知多个回调。
5. **异步 / 事件驱动**：数据什么时候来由设备决定，来了再调用你给的函数。
6. **接口稳定**：`Device` 代码不用变，功能可以不断扩展。
7. **控制反转**：原本是你主动调用写死函数，现在是外部把函数交给 `Device`，由 `Device` 在合适时机调用。

---

## 11. 注意事项

- **生命周期**：回调里引用的外部变量要活得比回调久。
- **线程安全**：回调可能在别的线程执行，共享数据要加锁。
- **异常**：回调里抛异常可能影响调用者，最好自己处理。
- **可读性**：回调太多、嵌套太深，代码会难懂。
- **空回调**：`std::function` 可能为空，调用前要 `if (cb_)`。
- **耗时操作**：回调里不要阻塞太久，否则可能卡住事件源线程。

---

## 12. 总结

> 回调 = 把“做什么”变成参数。
> 调用者只规定“长什么样”和“什么时候调用”，具体“怎么做”由外部传入。
> 所以它能解耦、能一个接口多种实现、能一个事件多个处理。
> 不是函数没有定义，而是调用者不定义，使用者来定义。
