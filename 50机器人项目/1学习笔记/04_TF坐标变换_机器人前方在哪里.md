# 04 · TF 坐标变换：机器人"前方"到底在哪

> 对应简历：**第 4 条**（建模与仿真：TF2 坐标树 `map → odom → base_link → 传感器`）。
> 这一篇讲清楚：为什么导航和激光离不开坐标系，你项目里这棵树是谁在维护的。

---

## 0. 一句话先记住

**TF 就是一张"零件相对位置表"。** 没有它，激光看到的一个障碍点，你根本不知道对应地图的哪个位置、在机器人左边还是右边。

---

## 1. 你项目里的坐标树长啥样

你机器人身上有一堆"坐标系"（frame），它们构成一棵**树**，父子关系是"谁相对谁"：

```
map                        ← 全局地图坐标系（不动）
 └─ odom                   ← 里程计坐标系（Nav2/AMCL 累加推算）
     └─ base_link          ← 机器人本体中心（底盘）
         ├─ chassis        ← 底盘外壳
         │   ├─ laser_frame   ← 激光雷达（挂在 chassis 上）
         │   └─ camera_link   ← 摄像头（挂在 chassis 上）
         └─ imu_link       ← IMU 惯性单元
```

这棵树从哪来的？三处代码各管一段：

| 树的一段 | 谁在维护 | 代码落点 |
|---|---|---|
| `base_link` 往下的子帧（chassis/laser/camera/imu） | `robot_state_publisher`，读 URDF 自动发 | `diff_drive_robot/urdf/robot.urdf` 里的 `<joint>` 定义 |
| `odom → base_link` | Gazebo 的 OdometryPublisher 插件发 | `config/gz_bridge.yaml` 第 9–15 行把 Gazebo 的 `tf` 桥接成 ROS 的 `/tf` |
| `map → odom` | AMCL 定位节点发（边走边修正） | `nav2_params.yaml`：AMCL 的 `global_frame_id: "map"`、`odom_frame_id: "odom"`、`base_frame_id: "base_link"` |

> 你**没有手写** TF 广播（不像有些教程自己写 `TransformBroadcaster`）。URDF、Gazebo、AMCL 已经替你发好了。你只要**懂这棵树的存在和意义**——这是面试被问"TF2 干嘛的"的标准答法。

---

## 2. 为什么必须有 TF（举个你能懂的例子）

激光雷达看到前方 1 米有个障碍。这个"前方 1 米"是**相对激光雷达自己**的坐标。
但机器人要导航，得知道"这个障碍在地图的哪个格子"。
TF 的作用就是：把"相对激光雷达的 1 米"一层层换算到"相对 base_link、再相对 odom、再相对 map"，最后得到地图坐标。
**没有 TF，传感器数据和地图对不上，导航直接瞎。**

---

## 3. 动手体验：自己发一个固定变换

想体会 TF 怎么"挂"一个坐标系，下面这个最小片段把 `lesson_base` 挂到 `map` 下面（固定偏移）。跑起来用 `ros2 run tf2_tools view_frames` 或 RViz 的 TF 插件就能看到这棵树多了一个节点。
> ⚠️ 需要 ROS2 环境（同 02 篇方式 A 的环境）。

```python
# tf_demo.py —— 把一个子坐标系静态挂到 map 下（教学用）
import rclpy
from rclpy.node import Node
from tf2_ros import StaticTransformBroadcaster
from geometry_msgs.msg import TransformStamped

class TfDemo(Node):
    def __init__(self):
        super().__init__("tf_demo")
        self._bc = StaticTransformBroadcaster(self)
        t = TransformStamped()
        t.header.frame_id = "map"          # 父
        t.child_frame_id = "lesson_base"   # 子
        t.transform.translation.x = 1.0    # 子在父的右边 1 米
        t.transform.rotation.w = 1.0       # 不旋转
        self._bc.sendTransform(t)
        self.get_logger().info("已发布 map -> lesson_base")

rclpy.init(); rclpy.spin(TfDemo())
```

## 4. 对应简历怎么答

被问"TF2 / 坐标树干嘛的" →
> "机器人身上有 map、odom、base_link 和传感器等多个坐标系，TF2 维护它们之间的相对变换树。传感器数据（比如激光）要换算到地图坐标系才能用于导航。我项目里这棵树由 URDF（robot_state_publisher）、Gazebo 和 AMCL 自动发布，我理解它的结构并依赖它。"

诚实点：你是**理解并依赖**这棵树，不是自己从零写 TF 广播。

---

## 5. 别踩坑（诚实底线）

- ❌ 别说"我自己写了 TF 广播把传感器挂上去"——是 URDF/Gazebo/AMCL 自动发的。
- ✅ 能说清 `map → odom → base_link` 每一层是谁、干嘛的，就够了。
- 记住：导航目标的坐标系是 `map`（见 02 篇），而机器人实时位姿在 `odom`/`base_link`，两者通过 TF 连起来。
