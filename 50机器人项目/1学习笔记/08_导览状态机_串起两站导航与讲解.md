# 08 · 导览状态机：怎么把"迎宾→导航→讲解→问答"串起来

> 对应简历：**第 3 条**（导航与导览调度：有限状态机 5Hz 串联流程，导航失败跳过展点继续巡游）。
> 这是你整个项目的"大脑"。这一篇贴着 `tour_node.py` 逐态讲，并给你一个能跑的迷你状态机体会"状态机思维"。

---

## 0. 一句话先记住

**状态机 = 一个"我现在在哪一步"的变量 + 每 0.2 秒看一次"发生了什么事件"，决定切到下一步。** 你项目里就是靠它把迎宾、导航、讲解、问答自动串成巡游。

---

## 1. 你项目里的 9 个状态（来自 `tour_node.py` 第 26–35 行）

```python
class State(IntEnum):
    INIT=0; IDLE=1; WAIT_VISITOR=2; NAVIGATE=3; GUIDE=4
    QA=5; NEXT=6; FINISH=7; PAUSED=8
```

正常巡游的路线（结合 `config/tour_points.yaml` 的 5 个展点：接待台→党史长廊→科技互动→成果展示→便民服务）：

```
INIT ──(Nav2 就绪)──> WAIT_VISITOR ──(检测到访客)──> NAVIGATE
   ↑                                                      │
   │                                                 (导航到达) 
   │                                                      ▼
FINISH <──(一轮结束)── NEXT <──(讲解完/超时)── GUIDE ──(讲解完)──> QA
                         │                                      │
                    (还有展点)                              (收到提问/超时)
                         │                                      │
                         └──────────────────────────────────────┘
```

---

## 2. 每个状态在代码里干啥（贴 `_loop()`，第 232 行起）

| 状态 | 干嘛 | 关键代码 |
|---|---|---|
| **INIT** | 等 Nav2 的 Action Server 就绪；就绪后自动进 WAIT_VISITOR（或 IDLE，看 `auto_start`） | 第 234–242 行 |
| **IDLE** | 啥也不干，等 `start` 指令 | 第 245–246 行 |
| **WAIT_VISITOR** | 等迎宾。`visitor_detector` 发 `/tour_guide/visitor_detected` 就播"您好"并进导航 | `_visitor_cb` 第 161–167 行 |
| **NAVIGATE** | 没在导航就发目标（`_send_nav_goal`），在导航就等结果 | 第 253–256 行、第 209–222 行 |
| **GUIDE** | 首次进入播报讲解词（`tour_points.yaml` 的 `speech`），停 `guide_pause=4` 秒 | 第 259–268 行 |
| **QA** | 播问"想了解什么"（`qa_prompt`），等提问或 `qa_timeout=12` 秒超时。`voice_input_sim` 会自动问一句，全程无需真人 | 第 271–286 行 |
| **NEXT** | 展点下标 +1；还有展点→NAVIGATE，没展点→FINISH | 第 289–300 行 |
| **FINISH** | 播结束语，等 5 秒；开了 `loop` 就回 WAIT_VISITOR 重新开始 | 第 303–314 行 |
| **PAUSED** | 暂停中啥也不干，等 `继续` 恢复 | 第 317–318 行 |

**人工接管指令**（`_cmd_cb` 第 135–159 行）：`start/继续`、`stop/停止`、`pause/暂停`、`next/跳过`、`home/回家`——都能在任意时刻插进来改流程。

## 3. 最关键的真实逻辑：导航失败怎么办

这是面试必问，也是你简历第 3 条的原话。看 `_goal_result_cb`（第 188–207 行）：

```python
if status == GoalStatus.STATUS_SUCCEEDED:
    self._change_state(State.GUIDE)        # 到了 → 讲解
elif status == GoalStatus.STATUS_CANCELED:
    pass                                    # 你手动取消了，正常
else:
    self._speak("导航出现异常，我将跳过该展点。")
    self._change_state(State.NEXT)          # ⚠️ 跳过当前展点，去下一个
```

> **诚实底线**：导航失败是"**跳过当前展点继续巡游**"，**不是回退重试、也不是状态回滚**。你简历写的是"跳过当前展点继续巡游"，照这句答，别加戏说"自动重规划重试"。

## 5. 对应简历怎么答

被问"状态机怎么实现的、导航失败怎么处理" →
> "用一个枚举定义 9 个状态，5Hz 定时器（每 0.2 秒）跑主循环 `_loop()`，根据当前状态和收到的事件（迎宾/导航结果/提问/指令）切换状态，把迎宾→导航→讲解→问答→下一展点串起来。导航失败就播报'跳过该展点'切到下一展点继续巡游，不回退。"

## 6. 别踩坑（诚实底线）

- ❌ 别说是"复杂的层次状态机/行为树"——你就是**一个枚举 + 一个轮询函数**，简单清晰，照实讲反而显实在。
- ❌ 导航失败别说"自动重新规划重试"——是跳过。
- ✅ 能照第 2 节把每个状态干啥说一遍，就是满分。5Hz、9 态、`guide_pause=4s`、`qa_timeout=12s` 这些数字你项目里真实存在，能脱口而出最佳。
