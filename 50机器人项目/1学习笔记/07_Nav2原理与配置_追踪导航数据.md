# 第七课：Nav2 原理与配置——小车收到目的地后，谁决定怎么走？

这一课围绕你已经跑通的导览项目。主要是终端观察和一次配置对比，有 RViz 时效果更直观。公司服务器没有原项目时，先读原理、代码和 YAML，实际导航留到虚拟机。

## 0．把 Nav2 拆成能理解的工作

| 模块 | 输入 | 工作与输出 |
|---|---|---|
| AMCL 定位 | 已知地图、雷达、里程计和 TF | 估计车在地图的位置，提供 `map → odom` |
| 全局规划 | 当前地图位置、目标、全局代价地图 | 计算从当前位置到目标的路线 |
| 局部控制 | 路线、当前位姿、附近障碍 | 选择当前要发的速度 |
| 行为/恢复 | 导航执行状态、失败情况 | 必要时等待、转向、后退等 |
| 速度平滑器 | 控制节点的速度命令 | 限制变化速度，把处理后的命令送给底盘 |
| BT Navigator | 导航 Action 目标 | 通过行为树协调这些模块，并回报任务结果 |

`Nav2` 是现成的 ROS2 导航框架，里面有多个节点和插件。不是一个“订阅位置后 if 判断”的单文件，也不是你本项目独立开发的算法。

本项目使用已知地图 + AMCL；启动过程中没有实时 SLAM 建图。全局规划插件是 NavFn，当前 `use_astar=false`，使用 Dijkstra 搜索；局部控制插件是 DWB。

先理解作用：全局规划选一条路，局部控制在附近尝试候选运动、结合路线和障碍评分，选择速度。今天不要求自己实现 Dijkstra、粒子滤波或 DWB。

## 1．沿一条真实数据链读项目

```text
Gazebo 雷达 → 桥接 → /scan → AMCL、障碍层
Gazebo 里程计 → 桥接 → /odom、TF
静态地图文件 → map_server → /map

客户端发送目的地 → /navigate_to_pose
    → BT Navigator 协调规划与控制
    → planner_server 规划路径 /plan
    → controller_server 计算 /cmd_vel_nav
    → velocity_smoother 输出 /cmd_vel
    → 桥接 → Gazebo 差速驱动 → 小车运动
```

代价地图不仅标记墙，还会把障碍周围一圈提高代价，让规划/控制尽量留距离；这叫膨胀层。它与给人分类、识别人脸是不同功能。

复制：

```python
import math
import time

import rclpy
from rclpy.node import Node
from rclpy.qos import qos_profile_sensor_data
from geometry_msgs.msg import PoseWithCovarianceStamped, Twist
from nav_msgs.msg import Path
from sensor_msgs.msg import LaserScan


class NavigationObserver(Node):
    def __init__(self):
        super().__init__('lesson_navigation_observer')
        self.counts = {'pose': 0, 'scan': 0, 'path': 0, 'velocity': 0}
        self.pose = None
        self.nearest = None
        self.path_points = 0
        self.maximum_speed = 0.0
        self.create_subscription(PoseWithCovarianceStamped, '/amcl_pose', self.on_pose, 10)
        self.create_subscription(LaserScan, '/scan', self.on_scan, qos_profile_sensor_data)
        self.create_subscription(Path, '/plan', self.on_path, 10)
        self.create_subscription(Twist, '/cmd_vel_nav', self.on_velocity, 10)
        self.timer = self.create_timer(1.0, self.report)

    def on_pose(self, msg):
        self.counts['pose'] += 1
        p = msg.pose.pose.position
        self.pose = (round(p.x, 2), round(p.y, 2))

    def on_scan(self, msg):
        self.counts['scan'] += 1
        distances = [v for v in msg.ranges
                     if math.isfinite(v) and msg.range_min <= v <= msg.range_max]
        self.nearest = round(min(distances), 2) if distances else None

    def on_path(self, msg):
        self.counts['path'] += 1
        self.path_points = len(msg.poses)

    def on_velocity(self, msg):
        self.counts['velocity'] += 1
        self.maximum_speed = max(self.maximum_speed, abs(msg.linear.x))

    def report(self):
        self.get_logger().info(
            f'NAV_OBSERVE: counts={self.counts}; pose={self.pose}; '
            f'nearest={self.nearest}; path_points={self.path_points}; '
            f'max_cmd_speed={self.maximum_speed:.3f}')


def main(args=None):
    rclpy.init(args=args)
    node = NavigationObserver()
    try:
        deadline = time.monotonic() + 15.0
        while rclpy.ok() and time.monotonic() < deadline:
            rclpy.spin_once(node, timeout_sec=0.1)
        node.report()
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        if rclpy.ok():
            rclpy.shutdown()


if __name__ == '__main__':
    main()
```

**观察节点没有 Publisher，不发送控制命令。** 收数据由它的订阅完成；数据产生仍来自原系统中的仿真、定位、规划、控制节点。

若停车时 `path=0` 或定位消息很少，不等于系统坏了：路线不一定持续重复发布，AMCL 更新也有运动阈值。新观察节点不能默认收到所有过去的事件。

## 4．先看懂五个配置项

打开原文件阅读：

```bash
nano ~/tour_guide_ws/src/diff_drive_robot/config/nav2_params.yaml
```

先阅读，不修改；退出时不保存。

| 项目当前配置 | 意思 |
|---|---|
| AMCL `min_particles=100`、`max_particles=400` | 粒子数量范围，影响定位计算量与表现 |
| `controller_frequency=10.0` | 控制循环期望频率，不保证高负载下都达到 |
| `FollowPath.max_vel_x=0.26`、`max_speed_xy=0.26` | DWB 平移候选速度上限，单位米/秒 |
| goal checker `xy_goal_tolerance=0.25` | 距目标的位置容差，配合朝向条件判断到达 |
| `inflation_radius=0.55` | 障碍周围的膨胀范围，影响绕障距离和通道可行性 |

这些是当前项目文件里的值，不是所有机器人的通用最佳值。降低频率/粒子数可减少计算，也有性能取舍。

复制：

```python
import sys
from pathlib import Path

import yaml


def main():
    if len(sys.argv) != 3:
        raise SystemExit('Usage: python3 make_slow_config.py ORIGINAL.yaml OUTPUT.yaml')
    original = Path(sys.argv[1]).expanduser().resolve()
    output = Path(sys.argv[2]).expanduser().resolve()
    if original == output or output.exists():
        raise SystemExit('Choose a NEW output file; do not overwrite the original')
    data = yaml.safe_load(original.read_text(encoding='utf-8'))
    follow = data['controller_server']['ros__parameters']['FollowPath']
    before = (follow['max_vel_x'], follow['max_speed_xy'])
    follow['max_vel_x'] = 0.15
    follow['max_speed_xy'] = 0.15
    # 两个值共同限制 DWB 的平移候选速度；保留平滑器现有上限。
    with output.open('x', encoding='utf-8') as file:
        yaml.safe_dump(data, file, allow_unicode=True, sort_keys=False)
    print(f'SLOW_CONFIG_CREATED: {output}; {before} -> (0.15, 0.15)')


if __name__ == '__main__':
    main()
```

运行：

```bash
python3 ~/ros2_lesson7_ws/make_slow_config.py \
  ~/tour_guide_ws/src/diff_drive_robot/config/nav2_params.yaml \
  ~/ros2_lesson7_ws/nav2_slow.yaml
```

第一次应看到 `SLOW_CONFIG_CREATED`。它只改副本中的两个 DWB 上限为 `0.15`。输出已存在时会拒绝覆盖；要再做副本，换一个新文件名。

只改磁盘 YAML 不会自动影响已经运行的节点。下面从冷启动加载这个副本，避免同时启动两套 Nav2。

## 8．面试时怎么讲

可以讲清楚：系统通过地图、雷达和 TF 建立定位与代价地图，由 Nav2 规划路线和生成速度；你集成导航 Action、配置展点、实现业务状态切换，并通过消息、TF、生命周期状态和日志排查问题。

不要把“接入 Nav2”和“独立实现导航算法”混在一起。真实做过参数对比后，才把这个调试实验说成自己的实践。

回答：AMCL 是否计算速度？路径为什么还不能直接驱动车轮？代价地图与静态地图有何区别？YAML 改了为何需要重启加载？

验证记录会区分观察节点测试与真实 Nav2 参数实验；后者需要你按本课操作。参考：[Nav2 Jazzy 控制服务端实现](https://raw.githubusercontent.com/ros-navigation/navigation2/jazzy/nav2_controller/src/controller_server.cpp)。
