# 机器人项目学习笔记：先看这里

这套教程面向“知道项目怎么启动，但还不会独立写 ROS2 程序”的阶段。以 Python 入门，最后用一课 C++ 对照。2026-10-13 已在你的 Ubuntu 虚拟机准备好课程源码和构建入口；现在可以跳过手工创建与复制，直接运行、观察、读关键代码。

教程文件可以在 Windows 阅读；ROS2、Gazebo 的运行命令在 Ubuntu 输入。Windows 文件所在的 D 盘路径不是 Ubuntu 工作区路径。

**当前先看第二课第 1～4 步，再看第三课。** 两份原文件已更新为直接运行版。其他课程中的建文件步骤可以用于理解结构，不必在已准备好的虚拟机上重做。

## 2．公司与家里分别怎么学

| 场景 | 可以先做 |
|---|---|
| 公司 Linux 服务器有 ROS2，只有 SSH | 第一、第三、第四课终端部分；第二课第 1～4 步；第八课 mock；第九课 |
| 公司服务器没有 ROS2 | 先阅读、建笔记、理解代码，确认系统和可安装条件，再搭环境 |
| Ubuntu 服务器有 Gazebo 和桥接，没有桌面 | 第五课的服务端与里程计练习，不打开 GUI |
| 家里现有 Ubuntu 虚拟机 | 第二课真实 Nav2、第四课坐标轴、第六课 RViz、第七课配置实验、第八课真实模式 |

不会因为“远程服务器”就天然缺少 ROS2，也不会因为有 Linux 就天然已经安装 ROS2。先检查：

```bash
cat /etc/os-release
command -v ros2
ls /opt/ros
echo "$DISPLAY"
```

目录不存在就保留报错文字。`DISPLAY` 为空表示当前终端没有指定图形显示，不妨碍普通 ROS2 节点运行；它不是 ROS2 是否安装的判断依据。

教程以 **Ubuntu 24.04 + ROS2 Jazzy + Gazebo Harmonic** 为基准。你的现有虚拟机可以直接用；公司服务器版本未知时先确认，不要把不同发行版的命令混用。

如果已经配置好 ROS2 Jazzy 软件源，但缺少练习组件，可按实际缺少的组件安装：

```bash
sudo apt update
sudo apt install ros-jazzy-ros-base python3-colcon-common-extensions \
  ros-jazzy-nav2-msgs ros-jazzy-tf2-ros python3-yaml
```

需要第五、第六课时，在兼容环境下补：

```bash
sudo apt install ros-jazzy-ros-gz ros-jazzy-rviz2
```

需要第九课且缺少编译工具时补 `build-essential`。这些不是从零添加软件源的完整安装过程；`Unable to locate package` 时先核对官方安装与系统版本，不要重复乱装。你现有虚拟机无需为了教程重装软件。

官方入口：[ROS2 Jazzy Ubuntu 安装](https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html)、[Gazebo 与 ROS 版本对应说明](https://gazebosim.org/docs/harmonic/ros_installation/)。

## 3．通信编号，别混用

| 用途 | ROS_DOMAIN_ID | 备注 |
|---|---:|---|
| 原导览项目、第二/七/八课真实导航 | 0 | 使用现有仿真与 Nav2 |
| 第一课 | 88 | 两个 Python 教学节点 |
| 第二课终端 Action 测试 | 89 | 模拟导航服务端，特殊测试坐标只在这里用 |
| 第三课 | 90 | Service |
| 第四课 | 91 | TF |
| 第五课 | 92 | 另有 `GZ_PARTITION=sbx_lesson5` |
| 第九课 | 94 | Python 模拟车 + C++ 控制器 |
| 第八课 mock | 95 | 不连接真实导航 |

`ROS_DOMAIN_ID` 控制 ROS2 通信分组，`GZ_PARTITION` 控制 Gazebo Transport 分组，二者不是一回事。

同一课不同终端的配置要一致。`export` 只影响当前终端及其之后启动的程序，不能改变早已启动的节点。这里假设节点在同一台 Linux 主机上运行，不包含公司与家里跨网络配置。

## 4．每课正确学习方法

1. 先说出“本课输入是什么、输出是什么”。
2. 照教程建文件，完整复制代码，跑到预期现象。
3. 只读教程点名的关键函数，不一次啃完所有库源码。
4. 改一个参数，先预测，再观察。
5. 回答本课自测问题，记下具体日志和结论。

不需要死背所有 API。优先理解：谁发布/订阅、谁发请求/答复、哪个回调处理什么、什么条件触发下一步。

Python 使用 `--symlink-install` 时，修改普通 `.py` 内容后保存并重启节点；改 setup.py 入口/依赖需要重新构建。C++ 修改 `.cpp` 后要构建并重启。运行中的进程不会自动换成你刚保存的新代码。

## 5．原项目的四条常用命令

先进入 `~/tour_guide_ws`，终端通信编号为 0。

```bash
# 完整启动，会清理并重新启动系统
bash run_all.sh --view

# 已经运行，只打开现有可视化
bash view_demo.sh

# 一轮结束后，从接待台重新安排导览
bash replay_tour.sh

# 结束整个仿真和导航栈
python3 tools/stop_stack.py
```

启动与“只打开窗口”不同。关闭 RViz 不会自动关闭后台仿真；关闭 Action 客户端也不保证 Nav2 的已接受目标被取消。

每次练习真实导航，只让一个业务程序安排目标。按照第二课先停止原自动导览，再发自己的目标。
