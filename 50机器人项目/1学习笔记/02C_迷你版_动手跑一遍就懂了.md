# 迷你导览：亲手跑一遍，就懂了

**这份是给你"动手体验"的，不是给你读的。**一共 3 条命令，5 分钟。

代码已经放在你虚拟机里了：`~/mini_tour/`。**不用建、不用编译、不用复制。**你只需要打开两个终端，敲命令，看屏幕。

---

## 二、开始之前：先看它长什么样（不用敲命令，看一眼）

迷你版的全部逻辑，就是下面这 6 句话：

```
WAIT_VISITOR  等人来          → 等 3 秒 → 客人到了
NAVIGATE      开过去          → 发一个 Action 目标，等它回"到了"
GUIDE         讲解            → 念一句话，停 2 秒
QA            问答            → 问一句，停 2 秒
NEXT          下一个          → 编号 +1，还有就回 NAVIGATE，没了就去 FINISH
FINISH        结束            → 说结束语，回到 WAIT_VISITOR 重新开始
```

**这就是"状态机"的全部。**一个不断循环的圈。

## 三、动手：两个终端，三条命令

### 第 1 步：打开终端 A（这个是"司机"）

在 Ubuntu 桌面打开一个终端，敲：

```bash
bash ~/mini_tour/run.sh
```

**按回车后，你会看到：**

```
[INFO] [1791900914] [fake_nav]: 假导航已上线，等待任务...
```

**别关这个终端。**它现在在等别人派活。这个角色就是你项目里 **Nav2** 扮演的。

> 这个"假导航"在干什么？它在假装自己是一辆车：收到任务后磨蹭 4 秒，然后说"到了"。**它不会真的动，你也不需要 Gazebo。**

### 第 2 步：新开终端 B（这个是"导览机器人"）

**另开一个终端窗口**（不是同一个），敲：

```bash
bash ~/mini_tour/demo.sh
```

**按回车后，盯住屏幕。**

### 第 3 步：看它自己跑起来

你会看到这样的滚动输出（**这是真实跑出来的**）：

```
[等人] 等待客人到来...
[等人] 客人来了！开始导览
[导航] 目标已发出 -> 接待台 (0.0, -3.5)
[导航] 接单了...（注意：车还没动）
[导航] 已到达！
[讲解] 这里是 接待台，欢迎参观。
[问答] 请问有什么问题？
[导航] 目标已发出 -> 党史长廊 (-4.5, 3.0)
[导航] 接单了...（注意：车还没动）
[导航] 已到达！
[讲解] 这里是 党史长廊，欢迎参观。
[问答] 请问有什么问题？
...
```

**让它自己跑，大概 40 秒走完 5 个展点**，然后看到：

```
========== 导览结束，感谢参观！ ==========
```

接着它**自动重新开始**——又回到"等人"了。想停下来，在终端 B 按 `Ctrl+C`。

## 四、看懂刚才发生了什么（对着屏幕看）

| 屏幕上这行 | 人话 | 在你真项目里的对应 |
|---|---|---|
| `[等人] 等待客人到来...` | 状态 = `WAIT_VISITOR` | 一样的 |
| `[等人] 客人来了！` | 条件满足，跳到下一个状态 | 真的项目靠 `visitor_detector` 检测 |
| `[导航] 目标已发出 -> 接待台 (0.0, -3.5)` | 状态 = `NAVIGATE`，**Action 下单** | 一样的，只是坐标从 yaml 读 |
| `[导航] 接单了...（注意：车还没动）` | **★ 最重要的两行之一** | 日志里的"导航目标已接受" |
| `[导航] 已到达！` | **★ 另一个最重要的一行** | 日志里的"导航到达" |
| `[讲解] 这里是 xxx` | 状态 = `GUIDE` | 一样的（真项目是喇叭念出来） |
| `[问答] 请问有什么问题？` | 状态 = `QA` | 一样的 |
| `-> 下一个坐标` | 状态 = `NEXT` → 回到 `NAVIGATE` | 一样的 |
| `====== 导览结束 ======` | 状态 = `FINISH` | 一样的 |

**注意 `接单了` 和 `已到达` 这两行是分开的**——这中间隔了 4 秒。这 4 秒就是"车在路上"。

❗ **这就是我前面说的"接受 ≠ 到达"。** 现在你亲眼看到了：接单的时候，后面还有 4 秒才到。

## 五、动手改一改（这一步才是真懂了）

**改之前不用关程序。但改完要重启才能生效**（`Ctrl+C` 然后重新跑）。

### 实验 1：让车开得慢一点（改"路上时间"）

打开 `fake_nav.py`：

```bash
nano ~/mini_tour/fake_nav.py
```

找到这一行：

```python
        for i in range(4):        # ← 4 就是"开 4 秒"
```

把 `4` 改成 `8`（开 8 秒）。保存（`Ctrl+X` → `Y` → 回车），重启两个终端。

**你会看到 `接单了` 和 `已到达` 之间的间隔变长了。**这就是"导航耗时"的感觉。

### 实验 2：改讲解词

打开 `mini_tour.py`：

```bash
nano ~/mini_tour/mini_tour.py
```

找到：

```python
                self.get_logger().info(f'[讲解] 这里是 {POINTS[self.idx]["name"]}，欢迎参观。')
```

改成：

```python
                self.get_logger().info(f'[讲解] 大家好，我是小智，这里是 {POINTS[self.idx]["name"]}。')
```

保存重启，看输出变了没有。

⭐ **这一步的意义**：你在`tour_points.yaml`里改讲解词，做的事和这里一模一样——**改文字不影响逻辑**。这就是"配置和代码分离"。

### 实验 3：加一个展点

在 `mini_tour.py` 里找到 `POINTS` 那一段，在最后加一行：

```python
    {"name": "茶水间",   "x": -2.0, "y": -1.0},
```

保存重启，看它是不是多走了一站。

### 实验 4：让导航"失败"，看它怎么办

打开 `fake_nav.py`，把 `handle.succeed()` 改成 `handle.abort()`：

```python
        handle.abort()        # 原来是 handle.succeed()
        return result
```

保存重启。你会看到：

```
[导航] 接单了...（注意：车还没动）
[导航] 失败了，跳过这个点
```

**然后它不会去讲解，直接跳下一个点。** 这就是你项目里"导航失败就跳过该展点"的逻辑。

## 六、现在回来看你的真项目

跑完上面这几个实验，你再打开 `~/tour_guide_ws/src/tour_guide/tour_guide/tour_node.py`，**你会发现你能看懂了**：

| 你的真项目 | 迷你版对应 | 差别 |
|---|---|---|
| `class State(IntEnum)` 第 26 行 | 顶部那 6 个字符串 | 真项目用数字 0-8，迷你版用文字 |
| `_loop()` 第 232 行 | `loop()` 函数 | 真项目 5Hz，迷你版 0.5 秒一次 |
| `_send_nav_goal()` 第 209 行 | `send_goal()` | 真项目坐标从 yaml 读，迷你版写在代码里 |
| `_goal_result_cb()` 第 188 行 | `on_result()` | **一模一样**：成功→讲解，失败→下一个 |
| `_feedback_cb()` 第 174 行 | 迷你版没有 | 真项目里是空函数（`pass`） |
| 5 个展点在 `tour_points.yaml` | `POINTS` 列表 | 真项目放配置文件，迷你版放代码里 |

❗ **唯一的"额外复杂度"**：你的真项目还多了"播报声音（TTS）""检测客人（visitor_detector）""问答匹配（qa_node）"，那都是**附加功能**，主干就是迷你版这样。
