## 1. 这个项目到底是个什么东西（完全人话版）

忘掉 ROS、Action、节点这些词。就说一件事：

> **一个装在轮子上的机器人，在一个展厅里，带着客人参观。**

它一整天就在重复这一件事，分 5 步：

| 步骤 | 人话描述 | 对应代码里的英文 |
|---|---|---|
| ① | 站在门口等人来 | `WAIT_VISITOR` |
| ② | 客人来了，开过去某个展台 | `NAVIGATE` |
| ③ | 到了，开口讲解这个展台 | `GUIDE` |
| ④ | 讲完问一句"有什么想问的吗"，等客人提问 | `QA` |
| ⑤ | 换下一个展台，回到步骤 ② | `NEXT` |
| ⑥ | 5 个展台都逛完了，说结束语 | `FINISH` |

**就这 6 个词。**你之前看到的 `NAVIGATE`、`GUIDE`、`QA`、`NEXT`、`FINISH`、`WAIT_VISITOR`，**就是这 6 件事的英文代号**，没有别的玄机。

`GUIDE` 是"讲解"的意思，`QA` 是 Question & Answer（问答），`NAVIGATE` 是"导航/开过去"，`NEXT` 是"下一个"。

❗ **误区：以为这些英文是 ROS2 规定的、必须背的专有名词。**
准确说法：**这些名字是这个项目的作者（也就是 AI）自己起的，随便叫什么都行。** 叫"等客人""开车""讲话"也完全合法。ROS2 完全不在乎你叫它什么。它们只是变量名。

那为什么还要用英文？两个实际原因：

1. 代码里中文变量名容易出编码问题；
2. 以后同事看代码，用英文更通用。

**所以：这些词你不需要"背"，你只需要知道"哦，这个英文说的是那件事"。**

## 4. 现在终于可以讲 Action 了——用你已经懂的话

### 4.1 Action 解决的问题：一件事要干很久

回想第 1 节的 6 个状态：

- `GUIDE`：说一句讲解词——**一瞬间**
- `QA`：等客人问——最多 12 秒
- `NEXT`：把编号加一——**一瞬间**
- `NAVIGATE`：**开车过去，要几十秒到一两分钟**

对于前面那些"一瞬间"的事，代码里直接做就行了，不需要什么特殊机制。

但 `NAVIGATE` 不一样。你想一想，现实里你叫一辆车，你会关心什么？

1. **它接不接我这一单？**（可能司机不来）
2. **现在到哪了？还有多远？**（等的过程很焦虑）
3. **最后到底送到没有？**（到了没有？失败了没有？）
4. **我能反悔取消吗？**（临时有事）

**Action 就是把这四件事变成正式的通信机制。** 仅此而已。

### 4.2 Action 用一句话定义

> **Action = 给"要花很久才能做完的事"设计的一套对话流程：下单 → 接单 → 报进度 → 交结果，随时可以取消。**

你项目里的导航就是它唯一的使用者。

### 4.3 三个关键词，对着"叫车"看

| 英文 | 叫车的类比 | 你项目里的实际内容 |
|---|---|---|
| **goal**（目标） | 你告诉司机"去 XX 路 3 号" | "去 (4.5, 3.0)，到了面朝左" |
| **feedback**（反馈） | 司机说"还有 2 公里" | Nav2 说"还剩 1.5 米" |
| **result**（结果） | 司机说"到了" / "去不了" | "成功到达" / "被取消" / "失败" |

❗ **误区：以为 goal 是"要送到的东西"。**
准确说法：**goal 就是"你的要求"**。导航里的 goal 是"去哪个坐标"；外卖里的 goal 是"送哪份饭"。它是**输入**，不是物品。

### 4.4 为什么不用别的方式？

这是面试必问，我用"叫车"给你讲清：

| 方式 | 叫车类比 | 为什么导航不用它 |
|---|---|---|
| **Topic**（话题） | **车载电台广播**：一直播路况，谁爱听谁听 | 广播没有"回话"的功能。你没法通过广播问"你到底来不来" |
| **Service**（服务） | **打一个电话**：问一句、答一句、挂断 | 打电话只能问一次答一次。司机没法在开车的 1 分钟里**一直**跟你说"还有 2 公里" |
| **Action** | **叫车 App** | 下单、司机接单、实时地图看进度、随时能取消、最后确认送达——**四样都有** |

❗ **最常见的误解：以为 Action 是"更高级的 Topic"。**
准确说法：它们解决的是**完全不同的问题**。Topic 解决"数据一直流"（比如车速每秒 20 次），Action 解决"一件耗时的事有没有干完"。**车速不可能用 Action 发**——那就成了每 0.05 秒叫一次车。

### 4.5 `ros2 interface show nav2_msgs/action/NavigateToPose` 是什么

你真问了这个问题，我正面答：

**`ros2` 是一个命令行工具。** 就像 `ls` 用来看文件、`cd` 用来换目录一样，`ros2` 是**用来查看和操作 ROS 系统的**。

命令拆开读：

```
ros2  interface  show  nav2_msgs/action/NavigateToPose
 │       │        │              │
 │       │        │              └── 我要看的东西的名字
 │       │        └── "显示给我看"
 │       └── "我要看接口（消息的格式）"
 └── ROS 的命令行工具
```

**它做的事：把"驱动这个动作需要填什么表格"打印出来。**

就像你第一次用快递 App，它要你填：收件人、地址、电话。这个命令就是打印"导航这个动作，需要填哪些字段"。

实测输出（我截取关键部分）：

```
#goal definition            ← 下单时要填的
geometry_msgs/PoseStamped pose     ← 填一个"位置"（含 x, y, 朝向）
string behavior_tree               ← 用哪套执行流程（可以不填）

---
#result definition          ← 干完后交付的
uint16 error_code                  ← 错误码，0 表示没出错
string error_msg                   ← 错误说明文字

---
#feedback definition        ← 干活过程中的播报
float32 distance_remaining         ← 还剩多少米（← 就是日志里那个数）
```

**两道 `---` 把内容切成三段，这正好对应 goal / result / feedback。**

❗ **误区：以为必须背下这个命令的输出。**
准确说法：**这是查手册用的，不用背。** 知道"有这个命令，忘了就敲一下"就够了。就像查字典，不需要背字典。

**✅ 一句话版本**

> Action 就是给"要花很久的事"准备的通信流程：下单、接单、报进度、给结果、可取消。导航用它是因为导航要几十秒，而 Topic 只能广播不能回话、Service 只能一问一答就结束。`ros2 interface show` 是查手册的命令，不用背。

```python
send_future.add_done_callback(self._goal_response_cb)
```

> 人话：**"拿一张空任务单 → 填上目标坐标 → 发出去 → 顺便登记好两个回调函数。"**
>
> 具体到你的项目：`self._idx` 是当前第几个展台（0 到 4），坐标是从 `tour_points.yaml` 读的。

### 6.4 第 174–176 行：进度回调（**故意空着**）

```python
def _feedback_cb(self, feedback_msg):
    # Nav2 会周期性发来当前进度，调试时可取消注释
    pass
```

> 人话：**司机一路上会不停跟你说"还有 1.5 公里、还有 1 公里…"，作者写了个接电话的函数，但里面什么都不做（`pass`）。**
>
> ❗ **误区：以为 `pass` = "没有反馈"。**
> 准确说法：**反馈一直在发**，只是这个项目选择不打印（因为真机上会刷屏）。第二课的教学版就是为了让你看到这个"还剩几米"，才专门做了个假的导航服务端。

### 6.5 第 188–207 行：收到最终结果后，决定下一步做什么

```python
if status == GoalStatus.STATUS_SUCCEEDED:
    self._change_state(State.GUIDE)      # 到了 → 开始讲解
elif status == GoalStatus.STATUS_CANCELED:
    self.get_logger().info("导航被取消")   # 被取消 → 不动
else:
    self._speak("导航出现异常，我将跳过该展点。")
    self._change_state(State.NEXT)        # 失败 → 跳过这个展台
```

> 人话：**"导航结束了，分三种情况处理：到了就去讲解；被取消了就等着；失败了就跳过这个展台。"**
>
> **这一小段就是整个项目最核心的 3 行逻辑。** 它决定了机器人下一步干什么。

**✅ 一句话版本**

> 打开 `tour_node.py` 我只需要看四处：开头给六个状态起名、第 76 行建 Action 客户端、第 209 行下单、第 188 行根据导航结果决定去讲解还是跳过。其余的都是细节。

## 7. 面试被问到怎么答

### 7.1 如果面试官问"你这个项目是什么"

> 这是一个 ROS2 的室内导览机器人仿真系统。机器人在展厅里从接待台出发，依次走到五个展点，到站播放讲解，接受提问并按关键词回答，走完一轮回到等待状态。底盘和导航算法用开源和成熟的 Nav2，我这边主要做的是业务调度、场景配置和仿真调试。

**注意：说"参与/我这边主要做"，不要说"我从零设计了"。**

### 7.2 如果问"Action 是什么，你怎么用的"

> 我项目里导览主控需要让机器人去各个展点，这个动作要几十秒，需要知道它接不接单、进行到哪了、最后到没到、以及能不能取消。ROS2 里 Topic 只能单向广播没法回话，Service 一问一答就结束了没法持续报进度，所以用 Action。我这边是 Action 客户端，向 Nav2 的 `/navigate_to_pose` 发目标，分别处理"接单确认""过程反馈""最终结果"三个回调，然后用结果驱动状态机跳转到讲解或者跳过。

### 7.3 如果问"你遇到什么问题"（这题一定要准备好）

诚实且有内容：

> 一开始我以为收到"目标已接受"就是到位了，结果发现车根本还没动，后来才理解 Action 的"接受"和"完成"是两次不同的答复，必须等最终结果才能进入讲解。

**这个"误区"是真的，是真的学习收获，比编一个问题强得多。**

### 7.4 不能夸大 / 别说的话

| 别说 | 为什么 |
|---|---|
| "我带一个团队做的" | 你是实习生，基调是"参与" |
| "我设计了路径规划算法" | 规划是 Nav2 的 NavFn/DWB，不是你的 |
| "我实现了 SLAM 建图" | 你项目里的地图是程序按几何生成的，**不是**边走边建 |
| "我做了语音识别" | 是**模拟**提问（随机挑问题），没有真麦克风 |
| "我做了视觉识别" | 摄像头在项目里是**注释掉的、禁用的** |
| "精度到厘米级" | 你没测过定位精度 |
| "导航成功率 100%" | 只能说"一轮测试中 5 个点全部到达" |

❤️ **记住一条：面试官最看重的不是"你会什么"，而是"你知不知道自己的边界在哪"。** 主动说"这块是 Nav2 做的，不是我做的"，反而是加分项。

**✅ 一句话版本**

> 讲项目先说业务（导览机器人循环走五个展点）、再说我用 Action 的原因（耗时、要反馈、可取消）、再说我的角色（业务层客户端，不是算法），最后主动划清边界（规划、定位、SLAM 都不是我做的）。

## 10. 一页背诵版（面试前 5 分钟扫一遍）

1. **项目是什么**：ROS2 室内导览机器人仿真，循环走 5 个展点，到站讲解 + 关键词问答。
2. **六个状态**：等人 → 开过去 → 讲解 → 问答 → 下一个 → 结束。（英文名只是代号，不用背）
3. **Action 是什么**：给"耗时的事"设计的通信流程，下单 → 接单 → 报进度 → 交结果，可取消。
4. **为什么导航用它**：Topic 只能广播不能回话，Service 一问一答就结束，只有 Action 能"边干边报进度还能取消"。
5. **我项目里在哪**：`tour_node.py` 是 Action 客户端，向 Nav2 的 `/navigate_to_pose` 下单。可现场用 `ros2 action info /navigate_to_pose` 证明。
6. **我的角色**：业务层。说去哪、到了讲什么、下一步走哪，都是我做；怎么去、怎么避障、速度多少，是 Nav2 做的。
7. **我踩过的坑**：误以为"目标已接受"就是到了，其实要等最终结果。
8. **边界**：SLAM、真实语音识别、视觉检测、定位精度——**都不是我做的**，别顺着面试官话头承认。
