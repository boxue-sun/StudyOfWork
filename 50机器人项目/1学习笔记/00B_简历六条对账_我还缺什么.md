## 二、逐条细拆（已会什么 / 还缺什么）

### 第 1 条 · 节点架构 ⚠️

**已会**：
- 5 个节点分别是谁、干什么（`launch/tour_guide.launch.py`）
- Topic 传状态：`/tour_guide/state`、`/tour_guide/visitor_detected`
- Action 下发导航目标：`/navigate_to_pose`

**还缺**：
- **Launch 怎么把 5 个节点一次拉起来**（`tour_guide.launch.py` 全文，约 80 行）
- **YAML 怎么驱动业务**（`tour_points.yaml` 5 个展点 + `qa_rules.yaml` 问答规则）
- 概念：**"改配置不用改代码不用编译"** 的具体机制

---

### 第 2 条 · 定位与导航 ❌ ← **缺口最大的一条**

配置文件：`src/diff_drive_robot/config/nav2_params.yaml`（293 行），顶层 13 个配置节：

```
amcl / bt_navigator / controller_server / local_costmap / global_costmap
map_server / map_saver / planner_server / smoother_server / behavior_server
waypoint_follower / velocity_smoother / lifecycle_manager_localization
```

**要学的 5 个点（面试直接对着问）**：

| 关键词 | 在配置里是什么 | 一句话要能讲清 |
|---|---|---|
| **AMCL** | `amcl` 节（L1），`robot_model_type: DifferentialMotionModel` | 已知地图上靠雷达匹配推算"我在哪" |
| **NavFn（Dijkstra）** | `planner_server` → `nav2_navfn_planner::NavfnPlanner`（L222） | 全局规划：从起点到终点算一条路 |
| **DWB** | `controller_server` → `dwb_core::DWBLocalPlanner`（L90） | 局部控制：沿路径实时发速度指令 |
| **代价地图** | `local_costmap`（obstacle+inflation）、`global_costmap`（static+obstacle+inflation） | 把障碍"变胖"一圈，留出安全距离 |
| **Lifecycle** | `lifecycle_manager_localization`（L290） | 导航栈各节点按顺序启动/激活 |

**面试注意**：这 5 个都是**Nav2 自带的**，你只是**配置**了它们。要说"我配置了/我调参了"，不能说"我实现了 AMCL"。

---

### 第 3 条 · 导航与导览调度 ⚠️ ← **最该先补**

**已会**：
- Action 下发 + 结果回调（`_goal_response_cb` / `_feedback_cb` / `_goal_result_cb`）
- `result` 才判断到达；`feedback` 不算
- 6 个状态名、`_change_state()` 是跳转动作

**还缺**：
- **20 次 `_change_state` 连成的那张网**（谁跳到谁、条件是什么）
- **导航失败分支**：`_goal_result_cb` 里 `else` → 播报"我将跳过该展点" → `_change_state(State.NEXT)`
- **5Hz 定时轮询**：`create_timer(0.2, self._loop)` 为什么这么设计
- **取消**：`_cancel_nav()` → `cancel_goal_async()`
- **两层状态机的区分**：业务状态机（你写的）vs Nav2 行为树（Nav2 的）

### 第 4 条 · 建模与仿真 ❌

**项目里的实物**：
```
urdf/robot.urdf、urdf/inertial_macros.xacro、urdf/robot.gazebo
launch/robot.launch.py、rsp.launch.py、mapping.launch.py、navigation.launch.py
config/gz_bridge.yaml、config/ekf.yaml（robot_localization 融合）
worlds/tour_hall.sdf、obstacles.world、empty.world
rviz/*.rviz（4 个观察窗口配置）
```

**要学的 5 个点**：

| 关键词 | 一句话要能讲清 |
|---|---|
| **URDF / Xacro** | 用 XML 描述小车的连杆和关节（轮子、底盘、雷达） |
| **TF2 坐标树** | `map → odom → base_link → 传感器`，回答"雷达看到的东西在世界哪儿" |
| **Gazebo Harmonic** | 仿真器，在里面搭场地、跑小车 |
| **ros_gz_bridge** | 把 Gazebo 的雷达/里程计话题翻译成 ROS2 话题 |
| **Xvfb / headless** | 没有显示服务器时也能跑仿真 |

---

### 第 5 条 · 访客检测 ✅ 已学透

- marker 坐标 `(1.5, -3.5)` + 距离阈值 `1.2 m` → 触发迎宾
- 参数化可配：`use_fake / marker_x / marker_y / distance_threshold / red_area_threshold`
- 默认 fake 模式；摄像头红色物体检测是**预留但默认关闭**的分支
- **面试红线**：不能说"用了视觉识别/人脸检测"

---

### 第 6 条 · 语音播报与问答 ❌ ← **最容易补**

- `tts_node.py`：离线 TTS 合成讲解音频，按展点播报（接的是 `/tour_guide/speech` 之类的输入）
- `qa_node.py`：**关键词匹配**的问答（不是大模型、不是语义理解）
- `qa_rules.yaml`：问答规则 + 讲解词，都在配置里
- **面试红线**：不能说"用了 NLP / 语音识别大模型"；要说"关键词匹配 + 配置驱动"
