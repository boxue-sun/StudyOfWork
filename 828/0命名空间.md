1.namespace命名空间实感
    命名空间是多个h文件中 防止命名冲突的
    例子（AI举例版）
        在C++中，如果不使用命名空间，当不同模块（如头文件或库）定义了同名的全局函数、变量或类型时，就会发生命名冲突（name collision）。这种冲突会导致编译错误（重复定义）或链接错误（多重定义），使代码无法正常工作。

下面是一个具体的例子，展示两个头文件各自定义了一个同名全局函数 `print`，当主文件同时包含它们时，会引发重复定义错误。

---

### 示例代码

**header1.h**  
```cpp
#ifndef HEADER1_H
#define HEADER1_H
#include <iostream>

void print() {
    std::cout << "This is header1's print." << std::endl;
}

#endif
```

**header2.h**  
```cpp
#ifndef HEADER2_H
#define HEADER2_H
#include <iostream>

void print() {
    std::cout << "This is header2's print." << std::endl;
}

#endif
```

**main.cpp**  
```cpp
#include "header1.h"
#include "header2.h"

int main() {
    print();    // 调用哪个 print()？编译/链接时会产生冲突
    return 0;
}
```

### 编译错误

使用 g++ 编译（例如 `g++ main.cpp`）会出现类似以下的错误信息：

```
/usr/bin/ld: duplicate symbol 'print()' in main.o and header1.o (或类似的重复符号错误)
```

因为两个头文件中的 `print` 函数都被展开到同一个编译单元中，链接器发现两个完全相同的函数定义，无法决定使用哪一个。

---

### 使用命名空间解决冲突

将每个头文件中的函数放入独立的命名空间，即可避免冲突：

**header1.h**  
```cpp
#ifndef HEADER1_H
#define HEADER1_H
#include <iostream>

namespace Lib1 {
    void print() {
        std::cout << "This is header1's print." << std::endl;
    }
}
#endif
```

**header2.h**  
```cpp
#ifndef HEADER2_H
#define HEADER2_H
#include <iostream>

namespace Lib2 {
    void print() {
        std::cout << "This is header2's print." << std::endl;
    }
}
#endif
```

**main.cpp**  
```cpp
#include "header1.h"
#include "header2.h"

int main() {
    Lib1::print();   // 明确调用 Lib1 中的 print
    Lib2::print();   // 明确调用 Lib2 中的 print
    return 0;
}
```

此时编译链接顺利通过，两个同名函数因命名空间作用域不同而互不干扰。

---

### 总结

- **不使用命名空间**：全局作用域中的同名实体（函数、变量、类等）会导致冲突，尤其是在大型项目或使用多个第三方库时。
- **使用命名空间**：将代码包裹在命名空间内，可有效隔离符号，避免名称污染和冲突，同时提高代码的可维护性和可读性。

这是C++中推荐的最佳实践之一——除非在极小的程序或临时测试中，否则应始终使用命名空间来管理全局名称。
