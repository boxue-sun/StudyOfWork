# C++ 模板（Template）核心知识点笔记

## 1. 本质：编译期的“代码模具”

模板不是函数，也不是类。它是**编译器用来生成具体函数/类的图纸**。

- **时机**：编译时（编译器根据你的调用，自动推导类型，生成对应的代码）。
- **别称**：泛型编程，属于**编译期多态**（静态多态）。

## 2. 两大分类

| 类型               | 关键字                   | 用途               | 例子                                           |
| :----------------- | :----------------------- | :----------------- | :--------------------------------------------- |
| **函数模板** | `template<typename T>` | 定义一个通用的函数 | `T max(T a, T b) { return a > b ? a : b; }`  |
| **类模板**   | `template<typename T>` | 定义一个通用的类   | `class BlockingQueue<T> { ... };` （你写的） |

## 3. 核心语法（速查表）

```cpp
// 声明
template <typename T>  // 或者 template <class T>（两者完全等价）
class MyClass {
public:
    T getData();
    void setData(const T& val);
};

// 类外定义成员函数（必须带上模板声明）
template <typename T>
T MyClass<T>::getData() {
    return data;
}

// 使用（显式实例化）
MyClass<int> obj;       // 告诉编译器：给我生成一份 T=int 的代码
MyClass<std::string> obj2;
```

## 4. 模板参数不止有“类型”

模板参数除了 `typename T`（类型参数），还可以是**非类型参数**（编译期常量）。

```cpp
template <typename T, size_t MaxSize>  // MaxSize 是编译期常量
class FixedArray {
    T arr[MaxSize];  // 数组大小在编译时确定
};

FixedArray<int, 100> buffer; // 生成一个能存100个int的数组
```

> **注意**：非类型参数只能是整型、枚举、指针、引用等，不能是浮点数或字符串。

## 5. `typename` 和 `class` 的区别

在声明模板参数时，**99% 的情况下两者完全等价**。

```cpp
template <typename T>  // 推荐写法（语义更清晰：T 是一种类型）
template <class T>     // 老写法（为了兼容 C 语言习惯）
```

> **唯一区别场景**：在访问**依赖类型**（如 `T::value_type`）时，必须加 `typename` 告诉编译器这确实是个类型，否则编译报错。

## 6. 模板的特化（Specialization）

针对特殊类型，你可以“定制”一份专属实现。

```cpp
// 通用模板
template <typename T>
class Printer { void print(T val) { cout << val; } };

// 针对 bool 的特化（全特化）
template <>
class Printer<bool> {
    void print(bool val) { cout << (val ? "真" : "假"); }  // 特殊处理
};
```

## 7. 编译原理（极其重要！记住这两条）

1. **两次编译**：模板本身编译一次（检查语法），实例化时（根据传入类型）再编译一次。
2. **头文件存储**：模板的**声明和定义必须都放在 .h 文件中**（或 .hpp）。不能把定义放在 .cpp，否则链接器找不到实例化后的代码（LNK2019 错误）。

## 8. 三大“坑”与注意事项

| 坑点                   | 解释                                                                                                            |
| :--------------------- | :-------------------------------------------------------------------------------------------------------------- |
| **代码膨胀**     | 你写`vector<int>` 和 `vector<float>`，编译器会生成两份独立的机器码，体积会变大。                            |
| **编译报错极长** | 模板报错是从嵌套的最深处炸出来的，动辄几千行。建议从**第一个 Error** 看起，或者用 C++20 的 Concept 约束。 |
| **不能分离编译** | 必须全部写在头文件里（前面第 7 条已强调）。                                                                     |

## 9. 进阶补充：模板的“移动语义”支持

你刚才的 `BlockingQueue` 如果要存 `unique_ptr`，必须支持**移动构造**。

```cpp
// 给 BlockingQueue 增加右值版本的 put（完美转发）
void put(T&& item) {  // 右值引用
    queue.push_back(std::move(item)); // 移动而不是拷贝
}
```

这就是为什么标准库里 `vector.push_back` 既有左值版本，又有右值版本的原因。

## 结合你的 `BlockingQueue` 一句话总结

你把 `T` 当作“占位符”，写了一个通用的线程安全容器。编译器在看到 `BlockingQueue<std::unique_ptr<Task>>` 时，**把代码中的每一个 `T` 替换成 `std::unique_ptr<Task>`**，生成一份专属的、存智能指针的机器码。

**记牢这一句**：**模板是编译时让代码“复制+替换”的工具，目的是为了避免针对不同数据类型重复写逻辑相同的代码。**
