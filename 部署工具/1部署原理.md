## 📖 远程部署的原理与实现逻辑

### 一、一句话概括

> 工具从 Excel 中取出每台设备的 IP/账号/密码，连上 SSH，把之前生成好的配置文件和地图/证书等文件通过 SFTP 上传到设备上，然后远程执行 `launch all` 命令重启服务，让新配置生效。

---

### 二、整体流程图

```
┌─────────────────────────────────────────────────────────────┐
│                    第1步：准备设备配置                        │
│                                                             │
│  从 Excel（MEC工参表）中提取每台设备的关键信息：              │
│    - MEC-IP、路口编号                                       │
│    - 智路OS用户名/密码（Docker层 SSH）                       │
│    - Linux主机用户名/密码（主机层 SSH）                      │
│    - 设备ESN                                                │
│                                                             │
│  同时找到上一步生成的 local/{路口}/{IP}/work_param_config.flag│
│  以及地图XML、RSI文件、各类证书文件                          │
│  → 打包成一个 DeviceConfig 对象                             │
└───────────────────────────┬─────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│              第2步：分批并发（每批最多20台）                  │
│                                                             │
│  for i in range(0, 总设备数, 20):                           │
│      batch = 设备列表[i : i+20]                             │
│      对 batch 中每台设备：                                   │
│          创建一个 DeployWorkParam（QRunnable）               │
│          丢进 QThreadPool 线程池并发执行                     │
└───────────────────────────┬─────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│           第3步：每台设备的部署过程（在线程池中）             │
│                                                             │
│  对每台设备，按顺序执行以下操作：                            │
│                                                             │
│  ① 校验 IP 合法性                                           │
│  ② SSH 连接到设备的 Docker 层（端口 57222）                  │
│  ③ SFTP 上传所有文件（见下方文件清单）                       │
│  ④ SSH 执行命令：launch all（重启智路OS模块）               │
│  ⑤ 关闭 SSH 连接                                            │
│                                                             │
│  如果任何一步失败 → 自动重试，最多 3 次                      │
└───────────────────────────┬─────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│              第4步：结果回传，刷新 UI                        │
│                                                             │
│  每台设备完成后，通过信号槽机制通知主线程：                   │
│    data_processed_signal → 更新表格中的"处理结果"列          │
│    统计成功数/失败数                                          │
└─────────────────────────────────────────────────────────────┘
```

### 四、核心代码逻辑拆解

#### 1️⃣ Handler（调度层）—— `deploy_work_param_handler.py`

**职责**：从 Excel 取出设备信息，构建 `DeviceConfig`，分批丢进线程池。

```
on_deploy_batch_start()
    │
    ├── 从 g_mec_data 提取 IP/路口/账号密码 → dict_list
    │
    ├── 创建 DevicesConfig（包含设备列表 + 配置文件路径 + MEC数据）
    │
    ├── 每 20 台一批：
    │     for device in batch:
    │         ├── _get_current_device_config()  → 构建 DeviceConfig
    │         │     ├── 找到对应的 work_param_config.flag 本地路径
    │         │     ├── 遍历 Excel 列，查 file_mapping 找到要上传的地图/证书文件
    │         │     ├── 所有文件加入 trans_files 列表：[(本地路径, 远程路径), ...]
    │         │     └── 填充 IP/端口/用户名/密码
    │         │
    │         ├── 创建 DeployWorkParam（QRunnable）
    │         └── thread_pool.start(opt_manager)  → 丢进线程池
    │
    └── 等待所有线程完成，通过信号更新 UI
```

#### 2️⃣ Pool（执行层）—— `deploy_work_param_pool.py`

**职责**：每台设备的具体部署操作（连 SSH → 传文件 → 执行命令）。

```
DeployWorkParam.run()
    │
    ├── 组装命令列表：
    │     execute_commands = [
    │         (TRANS, ""),              ← 第一步：传文件
    │         (LAUNCH_ALL, "chmod 755 /home/airos/script/launch && /home/airos/script/launch all")  ← 第二步：重启
    │     ]
    │
    ├── 重试循环（最多 3 次）：
    │     └── _transfer_or_command()
    │           │
    │           ├── ① 校验 IP 是否合法
    │           │
    │           ├── ② _create_ssh_client()
    │           │     └── paramiko.connect(IP, 端口57222, 用户名, 密码)
    │           │
    │           ├── ③ 遍历 execute_commands：
    │           │     ├── 如果是 TRANS → _transfer_files()
    │           │     │     └── sftp.put(本地文件, 远程目录)  ← 逐个上传
    │           │     │
    │           │     ├── 如果是 LAUNCH_ALL → _execute_shell_command()
    │           │     │     └── exec_command("launch all")  ← 重启服务
    │           │     │
    │           │     └── 如果任一步失败 → return 失败结果
    │           │
    │           └── finally: 关闭 SSH 连接
    │
    └── 发送信号通知结果
```

### 五、两个 SSH 端口的区别

设备有两层系统，各有一个 SSH 端口：

```
┌─────────────────────────────────────────┐
│            设备（路侧硬件）               │
│                                         │
│  ┌─────────────────────────────────┐    │
│  │     智路OS（Docker容器内）       │    │
│  │     SSH端口: 57222               │    │
│  │     用户名: root (智路OS用户名)   │    │
│  │     用途: 部署工参/执行launch all │    │
│  └─────────────┬───────────────────┘    │
│                │                         │
│  ┌─────────────┴───────────────────┐    │
│  │     Linux 主机                    │    │
│  │     SSH端口: 57022               │    │
│  │     用户名: root (linux系统用户名) │    │
│  │     用途: 系统级操作/重启设备     │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

工参部署主要用的是 **Docker 层（57222）**。

### 六、重试机制

```
第1次尝试 → 失败 → 等一会 → 第2次尝试 → 失败 → 等一会 → 第3次尝试 → 失败 → 标记为失败
                    ↓                                              ↓
                  成功 → 标记成功，break                          不再重试
```

- 默认重试 **3 次**
- SSH 超时 **6 秒**
- 命令执行超时 **60 秒**
- 一旦某一步失败就立即返回，不会继续执行后续步骤

### 八、一句话总结每个文件的职责

| 文件                             | 一句话                                                                           |
| -------------------------------- | -------------------------------------------------------------------------------- |
| `deploy_common.py`             | 定义`DeviceConfig`（单台设备配置）和 `DevicesConfig`（批量设备配置）数据结构 |
| `deploy_work_param_handler.py` | **调度层**：从 Excel 构建设备配置，分批分发到线程池                        |
| `deploy_work_param_pool.py`    | **执行层**：每台设备的具体操作——SSH连接、SFTP传文件、执行命令、重试      |
| `ssh_utils.py`                 | SSH 底层工具：封装了 paramiko 的连接/命令执行/文件上传                           |

### 九、完整部署链路（端到端）

```
读Excel → 生成JSON配置文件 → 构建DeviceConfig → 分批并发(20台/批)
→ SSH连接(57222) → SFTP上传(工参+地图+证书) → 执行launch all
→ 关闭连接 → 结果回传UI → 成功/失败统计
```

这就是整个远程部署的完整原理和实现逻辑！
