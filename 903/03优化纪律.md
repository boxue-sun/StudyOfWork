
## 简历项目描述

---

### 项目名称

**基于DDS的交通流量统计服务（traffic_flow）**

---

### 项目背景

交通流量统计微服务，通过DDS中间件订阅路侧感知设备发布的车辆轨迹数据（RSM JSON），对车道级车辆信息进行实时统计，输出流量、排队、车头时距等交通指标。

---

### 我做的改动

#### 1. 检测器管道架构重构

**问题：** 原有 snapshot（1s）和 accumulate（5min）两条检测器管道各自独立，代码重复，扩展新周期（如信号周期）需要改多处代码。

**方案：** 设计统一的 `OutputChannel` 抽象，将不同周期的检测器管道合并：

```cpp
struct OutputChannel {
    std::string cycle_type;              // snapshot / accumulate_5min / signal_cycle
    std::vector<std::unique_ptr<AccumulateDetector>> detectors;
    uint64_t interval_ms;                // 输出周期
    bool should_output(current_time, spm); // 统一触发判断
};
```

- 所有检测器统一继承 `AccumulateDetector`，实现 `update()` + `calculate_once()` 接口
- 删除冗余的 `SnapshotDetector` 基类及 `SnapshotVolumeDetector`、`SnapshotQueueDetector` 等子类
- `detect()` 主循环统一遍历 `_output_channels`，消除重复代码
- 新增 `signal_cycle` 周期，通过 `SignalPhaseManager::check_and_consume_cycle_boundary()` 在信号灯绿→红→绿边界触发输出

#### 2. 车头时距（Headway）检测器开发

**需求：** 1s 输出逐车头时距明细，5min 输出平均值，信号周期输出周期内平均 headway。

**实现：** 新增 `AccumulateHeadwayDetector`，继承 `AccumulateDetector`：

- 复用 `StopLineCrossingTracker` 进行停止线过线检测（几何相交算法）
- 自行维护车辆过线时间戳，计算车头时距（Headway）和车头间距时间（Gap）
- `update()` 每帧累积过线车辆的时间差，`calculate_once()` 输出平均值并清零
- 通过配置文件 `detector_cycles` 注册到 snapshot、accumulate_5min、signal_cycle 三个 channel，由 `OutputChannel` 的 `interval_ms` 或信号灯触发控制输出节奏

#### 3. 配置驱动机制

检测器类型和输出周期完全由 JSON 配置驱动，新增检测器类型只需：

1. 实现 `AccumulateDetector` 子类
2. 在 `build_detectors_from_config()` 的 if-else 中加一个分支
3. 在配置文件的 `detector_cycles` 中添加对应 type

| 技术点                    | 说明                                                               |

| **多态 + 工厂模式** | 检测器通过基类指针统一管理，配置驱动动态创建                       |

### 面试话术（30秒版）

> 我负责交通流量统计服务的检测器架构重构和车头时距功能开发。原有架构中1秒快照和5分钟累积是两套独立管道，代码重复且难以扩展。我设计了统一的 OutputChannel 抽象，将所有检测器合并到 AccumulateDetector 基类下，通过配置文件的 interval_ms 控制输出周期，并新增了信号灯周期触发。同时开发了车头时距检测器，复用停止线过线检测工具，实现了1秒逐车明细、5分钟平均值、信号周期平均值三种输出模式。整个架构配置驱动，新增检测器只需实现接口加配置，不需要改框架代码。

### 面试话术（追问版）

**Q：OutputChannel 怎么统一不同周期的？**

> 所有检测器都是 update() 累积 + calculate_once() 输出清零。区别在于 should_output() 的判断逻辑——snapshot 和 accumulate_5min 用 interval_ms 定时判断，signal_cycle 调用 SignalPhaseManager 检测信号灯相位边界。同一个检测器类，放在不同 channel 里就有不同的输出节奏。

**Q：车头时距怎么算的？**

> 用 StopLineCrossingTracker 检测车辆是否穿过停止线（轨迹线段与停止线线段的几何相交），记录每辆车的过线时间戳，相邻两辆车的时间差就是 headway。1s 周期输出逐车明细数组，5min 和信号周期输出算术平均值。

**Q：为什么用 AccumulateDetector 统一？**

> 因为 snapshot 本质上也是"累积1秒的数据然后输出清零"，和 accumulate 的逻辑完全一样，只是周期不同。统一后消除了 compute()/reset() 和 update()/calculate_once() 两套接口的重复代码。
