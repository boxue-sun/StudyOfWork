# AIROS 2.0 容器部署笔记

## 一、脚本作用

`build_airos_container.sh` 不是编译程序，而是：

1. 用 `docker load` 导入 Docker 镜像包；
2. 可选：把配置包解压到 `/work/airos2.0/`；
3. 删除旧容器 `airos_2_0_shiyan_rs_test`；
4. 用镜像重新创建并启动容器。

关键挂载：

```bash
-v /work/airos2.0:/home/airos
```

意思是：

- 宿主机目录：`/work/airos2.0`
- 容器内目录：`/home/airos`
- 两边内容互通。

容器启动参数：

```bash
--name airos_2_0_shiyan_rs_test
--restart=always
--stop-timeout 20
--privileged=true
--net=host
--shm-size 2G
-v /work/airos2.0:/home/airos
```

因为用了 `--net=host`，容器端口直接开在宿主机上。

## 二、正确用法

假设脚本、镜像包路径如下：

```text
脚本：/data/sunboxue/十堰/脚本/build_airos_container.sh
镜像：/data/sunboxue/十堰/镜像/airos_2_0_shiyan_rs_202609201557.tar.gz
```

运行：

```bash
cd "/data/sunboxue/十堰/脚本"

sudo bash ./build_airos_container.sh \
  /data/sunboxue/十堰/镜像/airos_2_0_shiyan_rs_202609201557.tar.gz
```

如果有配置包：

```bash

  /data/sunboxue/十堰/镜像/airos_2_0_shiyan_rs_202609201557.tar.gz \
  /path/to/config.tar.gz
```

## 三、我遇到的问题与解决

### 1. 不理解脚本作用

已理解：

- 导入镜像；
- 可选解压配置；
- 重建并启动容器；
- 配置/数据通过 `/work/airos2.0` ↔ `/home/airos` 挂载。

### 2. `sudo` 密码输错

报错：

```text
Sorry, try again.
```

解决：重新输入正确密码。输入时不显示字符是正常的。

### 3. `command not found`

报错：

```text
sudo: ./build_airos_container.sh: command not found
```

原因：

- 实际文件名可能是 `build_airos_container.s`，不是 `.sh`；
- 或者当前目录不对。

解决：

```bash
ls -la
mv build_airos_container.s build_airos_container.sh
chmod +x build_airos_container.sh
```

或者直接用 `bash` 调：

```bash
sudo bash ./build_airos_container.s 镜像包路径
```

### 4. `docker load` 报 `unexpected EOF`

报错：

```text
Error processing tar file(exit status 1): unexpected EOF
Failed to load Docker image ...
```

原因：镜像包不完整或损坏。

检查：

```bash
ls -lh airos_2_0_shiyan_rs_202609201557.tar.gz
gzip -t airos_2_0_shiyan_rs_202609201557.tar.gz
tar -tzf airos_2_0_shiyan_rs_202609201557.tar.gz > /dev/null
```

解决：重新获取/重新传输完整的镜像包。后来重新运行成功加载所有 layer。

### 5. 最终成功

关键输出：

```text
Loaded image: cictci/airos:airos_2_0_shiyan_rs_202609201557
Docker image successfully loaded.
No config tar file specified, skipping config extraction.
Container airos_2_0_shiyan_rs_test started successfully.
```

说明：

- 镜像已导入本机 Docker；
- 容器已创建并启动；
- 没传配置包，所以跳过了配置解压。

## 五、常用验证命令

```bash
# 看容器是否在运行
docker ps | grep airos_2_0_shiyan_rs_test

# 看日志
docker logs -f airos_2_0_shiyan_rs_test

# 进容器
docker exec -it airos_2_0_shiyan_rs_test bash

ls /home/airos

# 宿主机看挂载目录
ls -la /work/airos2.0

# 看镜像
docker images | grep airos
```

## 六、查看容器端口

因为容器用了 `--net=host`，`docker port` 基本没用。

先确认网络模式：

```bash
docker inspect -f '{{.HostConfig.NetworkMode}}' airos_2_0_shiyan_rs_test
```

输出应为：

```text
host
```

查看监听端口：

```bash
# 宿主机上看，等价于容器内
ss -lntp

# 或
netstat -lntp

# 只看 AIROS 相关
ss -lntp | grep -i airos

# 容器内看
docker exec airos_2_0_shiyan_rs_test ss -lntp
```

看镜像声明的端口：

```bash
docker inspect -f '{{.Config.ExposedPorts}}' airos_2_0_shiyan_rs_test
```

注意：这只是镜像声明，实际有没有监听还要看 `ss -lntp`。

## 七、注意事项

1. 脚本必须 root 运行。
2. 镜像名按文件名拼：

   ```bash
   cictci/airos:$(basename "$FILE" .tar.gz)
   ```

   例如传入 `airos_2_0_shiyan_rs_202609201557.tar.gz`，期望镜像名就是：
   ```text
   cictci/airos:airos_2_0_shiyan_rs_202609201557
   ```
3. 容器名固定为 `airos_2_0_shiyan_rs_test`，重复运行会先删除旧容器。
4. 删容器会丢容器可写层里的数据，但挂载目录 `/work/airos2.0` 不会丢。
5. 配置放宿主机 `/work/airos2.0`，容器内 `/home/airos` 能看到。
6. `--privileged=true` 和 `--net=host` 权限较高，只在可信环境使用。

## 八、一句话总结

**脚本 = 导入 Docker 镜像 + 可选解压配置到 `/work/airos2.0` + 删除旧容器 + 用镜像重新启动名为 `airos_2_0_shiyan_rs_test` 的容器。容器内 `/home/airos` 就是宿主机 `/work/airos2.0`，端口因 `--net=host` 直接开在宿主机上。**
