
## relayDeployTool 部署功能 Bug 记录

### Bug 1: Windows 路径分隔符导致 SFTP 上传失败（静默失败）

**现象**：部署结果显示"重启中继模块成功"，但目标机器上没有文件。

**原因**：`os.path.join()` 在 Windows 上生成反斜杠 `\`，导致远程路径变成混合路径：

```
/work/sunboxue/config\work_param_config.flag  ← 错误
```

Linux SFTP 无法识别，文件上传到了错误位置或静默失败。

**修复**：`opt_relay_deploy/deploy_relay_handler.py` 第 78 行

```python
# 修复前
remote = os.path.join(remote_dir, os.path.basename(cfg_path))

# 修复后
remote = remote_dir.rstrip("/") + "/" + os.path.basename(cfg_path)
```

**教训**：远程路径必须始终用正斜杠 `/`，不能用 `os.path.join`（会随操作系统变化）。

### Bug 2: 远程目录不存在导致传输失败

**现象**：部署显示"传输文件异常"，目标机器上没有 `/home/airos/common_config/` 目录。

**原因**：测试机器不是 AIROS 系统，没有预建目录结构。`sftp.put()` 写入不存在的目录会抛异常。

**修复**：`basic/ssh_opt_base.py` 的 `_transfer_files` 方法中增加自动创建目录逻辑：

```python
# 上传前检查远程目录是否存在，不存在则递归创建
remote_dir = remote_path.rsplit("/", 1)[0]
try:
    sftp.stat(remote_dir)
except FileNotFoundError:
    self._mkdir_p(sftp, remote_dir)
```

新增 `_mkdir_p` 方法（类似 `mkdir -p`）递归创建远程目录。

**教训**：SFTP 上传前必须确保远程目录存在，不能假设目标机器有标准目录结构。

---

### Bug 3: 基类只传递核心列，子类无法访问证书路径列

**现象**：`_prepare_device` 只能拿到 5 个核心列（IP、路口、用户名、密码、Sn），无法访问 Excel 中的证书路径列。

**原因**：`batch_start` 中用 `g_columns_to_extract` 提取数据传给子类，只包含 SSH 连接所需的列。

**修复**：`basic/opt_event_handler_base.py` 改为传递完整行数据：

```python
# 修复前
row = self.devices_config.data_list[device_index]  # 只有 5 列

# 修复后
full_row = global_data.g_relay_data.iloc[device_index].to_dict()  # 所有列
```

**教训**：子类需要访问完整行数据时，基类应传递完整 DataFrame 行而非仅提取列。

---

### Bug 4: 每台设备远程部署目录硬编码为全局常量

**现象**：所有设备的 flag 都上传到同一个全局目录 `/home/airos/common_config/`，无法为不同设备指定不同目录。

**原因**：远程目录写死在 `global_data.relay_config_remote_dir_path`。

**修复**：

1. `global_data.py` 的 `g_columns_to_extract` 新增 `"远程配置目录"` 列
2. `data_model/deploy_common.py` 的 `DeviceConfig` 新增 `config_remote_dir` 字段
3. `opt_event_handler_base.py` 的 `_get_conn_info` 提取该列值
4. `deploy_relay_handler.py` 优先使用设备自己的目录：

```python
remote_dir = dc.config_remote_dir or global_data.relay_config_remote_dir_path
```

**教训**：每台设备的部署路径可能不同，应支持从工参表动态指定。

---

### Bug 5: SSH 连接和传输错误日志不够详细

**现象**：部署失败时只显示"传输文件异常: ..."，看不到具体错误原因。

**原因**：异常信息被截断，SSH 连接日志缺失。

**修复**：`basic/ssh_opt_base.py` 增加详细日志：

```python
# SSH 连接前后都打日志
logger.info(f"正在SSH连接 {ip}:{port} 用户={username}")
logger.info(f"SSH连接成功 {ip}")
logger.error(f"SSH连接失败 {ip}:{port} 用户={username} 错误: {e}")

# 传输异常包含异常类型
self.info = f"传输文件异常: {type(e).__name__}: {e}"
```

**教训**：网络操作必须记录连接前后的详细日志，异常信息要包含类型名。

## 总结

| Bug            | 根因                                   | 影响               |
| -------------- | -------------------------------------- | ------------------ |
| 路径分隔符     | `os.path.join` 在 Windows 生成 `\` | 文件上传到错误位置 |
| 远程目录不存在 | 未自动创建目录                         | SFTP 抛异常        |
| 只传核心列     | 基类设计缺陷                           | 子类无法访问证书列 |
| 目录硬编码     | 全局常量                               | 无法适配不同设备   |
| 日志不详细     | 异常信息被截断                         | 难以排查问题       |
