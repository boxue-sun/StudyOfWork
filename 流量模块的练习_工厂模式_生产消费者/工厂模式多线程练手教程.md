## 第 1 步：任务基类 — `include/task.h`

### 知识点
- **纯虚函数** = C++ 的接口，类似 Java 的 interface
- 工厂模式返回的都是基类指针，通过虚函数调用子类的实现

### 对照项目
项目中 `AccumulateDetector` 就是这样的基类，定义了 `update()` 和 `calculate_once()` 纯虚函数。

### 请手敲以下代码

```cpp
#ifndef TASK_H
#define TASK_H

#include <string>
#include <iostream>

// ===== 任务类型枚举 =====
// 用 enum class 比裸 enum 更安全（有作用域，不会隐式转 int）
// 项目中 DetectorType 就是这样定义的
enum class TaskType {
    COUNT,   // 计数任务
    SUM,     // 求和任务
    UNKNOWN
};

// ===== 任务基类 =====
class Task {
public:
    explicit Task(const std::string& name) : _name(name) {}
    virtual ~Task() = default;

    // 纯虚函数：子类必须实现
    virtual void execute() = 0;

    // 获取任务名称
    std::string get_name() const { return _name; }

    // 获取任务类型（用于调试）
    virtual TaskType get_type() const = 0;

private:
    std::string _name;
};

// ===== 具体任务1：计数任务 =====
class CountTask : public Task {
public:
    CountTask(const std::string& name, int count)
        : Task(name), _count(count) {}

    void execute() override {
        int sum = 0;
        for (int i = 0; i < _count; ++i) {
            sum += 1;
        }
        std::cout << "[CountTask] " << get_name()
                  << " 计算结果: " << sum << std::endl;
    }

    TaskType get_type() const override { return TaskType::COUNT; }

private:
    int _count;
};

// ===== 具体任务2：求和任务 =====
class SumTask : public Task {
public:
    SumTask(const std::string& name, int from, int to)
        : Task(name), _from(from), _to(to) {}

    void execute() override {
        int sum = 0;
        for (int i = _from; i <= _to; ++i) {
            sum += i;
        }
        std::cout << "[SumTask] " << get_name()
                  << " 计算结果: " << sum << std::endl;
    }

    TaskType get_type() const override { return TaskType::SUM; }

private:
    int _from;
    int _to;
};

#endif // TASK_H
```

### 检查要点
- [ ] `Task` 是抽象类（有纯虚函数，不能直接实例化）
- [ ] `CountTask` 和 `SumTask` 都用 `override` 关键字重写虚函数
- [ ] 构造函数用 `explicit` 防止隐式转换

## 第 2 步：阻塞队列 — `include/blocking_queue.h`

### 知识点（重点！面试高频考点）
- **mutex（互斥锁）**：保证同一时刻只有一个线程访问共享数据
- **condition_variable（条件变量）**：让线程在"队列为空"时睡觉，有数据时被唤醒
- **lock_guard**：RAII 风格的锁管理，构造时加锁、析构时自动解锁，防止忘记解锁
- **while 循环检查条件**：防止"虚假唤醒"（spurious wakeup）

### 对照项目
项目中 `BlockingQueue.h` 几乎一模一样的结构！它用 `MutexLock` + `Condition` 封装了同样的逻辑。
`TrafficFlowFactory::detect()` 方法里的 `_input_buffer.take()` 就是在调用这个队列。

### 请手敲以下代码

```cpp
#ifndef BLOCKING_QUEUE_H
#define BLOCKING_QUEUE_H

#include <mutex>
#include <condition_variable>
#include <deque>

// 模板类：可以存放任意类型
template <typename T>
class BlockingQueue {
public:
    explicit BlockingQueue(size_t capacity = 100)
        : _capacity(capacity) {}

    // 放入数据（生产端调用）
    void put(const T& item) {
        std::unique_lock<std::mutex> lock(_mutex);  // 加锁

        _queue.push_back(item);

        // 如果超过容量，丢弃最旧的（和项目里一样）
        if (_capacity > 0 && _queue.size() > _capacity) {
            _queue.pop_front();
        }

        lock.unlock();          // 先解锁
        _not_empty.notify_one(); // 再通知：有数据了！
    }

    // 取出数据（消费端调用）—— 如果没有数据会阻塞等待
    T take() {
        std::unique_lock<std::mutex> lock(_mutex);  // 加锁

        // ★ 关键：用 while 而不是 if，防止虚假唤醒
        // 面试必问：为什么用 while？
        // 答：因为 condition_variable 可能在没有 notify 的情况下醒来
        //     （叫 spurious wakeup），所以醒来后必须再检查一次条件
        while (_queue.empty()) {
            _not_empty.wait(lock);
            // wait() 做了三件事：
            //   1. 解锁（让其他线程可以 put）
            //   2. 让自己睡觉（不占 CPU）
            //   3. 被唤醒后重新加锁
        }

        T front = std::move(_queue.front());
        _queue.pop_front();
        return front;
        // lock 在这里析构，自动解锁
    }

    size_t size() const {
        std::lock_guard<std::mutex> lock(_mutex);
        return _queue.size();
    }

    bool empty() const {
        std::lock_guard<std::mutex> lock(_mutex);
        return _queue.empty();
    }

private:
    mutable std::mutex          _mutex;        // 互斥锁
    std::condition_variable     _not_empty;    // 条件变量：队列非空
    std::deque<T>               _queue;        // 底层存储
    size_t                      _capacity;     // 容量上限
};

#endif // BLOCKING_QUEUE_H
```

### 检查要点
- [ ] `put()` 和 `take()` 都先加锁再操作数据
- [ ] `take()` 用 `while` 循环检查 `empty()`，不是 `if`
- [ ] `notify_one()` 在 `unlock()` 之后调用（性能优化，和项目里一样）
- [ ] `size()` 和 `empty()` 也加了锁（const 方法访问可变成员要用 `mutable`）

### 思考题（面试可能会问）
> **Q：`unique_lock` 和 `lock_guard` 有什么区别？**
> - `lock_guard`：简单粗暴，构造加锁、析构解锁，不能手动操作
> - `unique_lock`：更灵活，可以手动 lock/unlock，condition_variable::wait() 必须用它
>
> **Q：为什么 `notify_one()` 放在 `unlock()` 后面？**
> - 放在锁里面也行，但效率低：被唤醒的线程发现锁还被占着，又要等一次
> - 放在 unlock 后面：被唤醒的线程可以直接拿锁，少一次上下文切换
> - 项目里的 `BlockingQueue::put()` 也是这个顺序

## 第 3 步：工厂类 — `include/task_factory.h` + `src/task_factory.cpp`

### 知识点
- **工厂模式**：把"创建对象"的逻辑集中管理，调用者不需要知道具体类名
- 返回基类指针 `Task*`，调用者通过虚函数多态使用

### 对照项目
项目中 `TrafficFlowFactory::create_detector()` 就是一个静态工厂方法，
根据 `DetectorType` 枚举 switch-case 创建不同的检测器。

### 请手敲头文件 `include/task_factory.h`

```cpp
#ifndef TASK_FACTORY_H
#define TASK_FACTORY_H

#include "task.h"
#include <memory>

class TaskFactory {
public:
    // 静态工厂方法：根据类型创建对应的任务对象
    // 返回 unique_ptr 自动管理内存（项目中也有用 new 的，但推荐智能指针）
    static std::unique_ptr<Task> create_task(TaskType type, const std::string& name);
};

#endif // TASK_FACTORY_H
```

### 请手敲实现文件 `src/task_factory.cpp`

```cpp
#include "task_factory.h"

std::unique_ptr<Task> TaskFactory::create_task(TaskType type, const std::string& name) {
    switch (type) {
        case TaskType::COUNT:
            // 创建一个计数任务，数字随便写死，练习用
            return std::make_unique<CountTask>(name, 1000);

        case TaskType::SUM:
            // 创建一个求和任务，1+2+...+100
            return std::make_unique<SumTask>(name, 1, 100);

        default:
            std::cerr << "[TaskFactory] 未知任务类型!" << std::endl;
            return nullptr;
    }
}
```

### 检查要点
- [ ] 工厂方法是 `static` 的，不需要创建工厂对象就能调用
- [ ] 返回 `std::unique_ptr<Task>`，调用者不需要手动 delete
- [ ] switch 有 `default` 分支处理异常情况

## 第 4 步：处理器 — `include/processor.h` + `src/processor.cpp`

### 知识点（多线程核心）
- **std::thread**：创建线程
- **std::atomic**：原子变量，不需要加锁的线程安全变量
- **线程生命周期管理**：构造时启动、析构时 join 等待退出
- **状态机**：用 atomic 枚举控制线程运行/退出

### 对照项目
项目中 `TrafficFlowFactory` 构造函数里：
```cpp
_working_thread = std::make_unique<std::thread>(&TrafficFlowFactory::detect, this);
```
析构函数里：
```cpp
_status = FactoryStatus::EXIT;
_working_thread->join();
```
这就是完全一样的模式！

### 请手敲头文件 `include/processor.h`

```cpp
#ifndef PROCESSOR_H
#define PROCESSOR_H

#include "task.h"
#include "blocking_queue.h"
#include "task_factory.h"

#include <thread>
#include <atomic>
#include <vector>
#include <functional>
#include <string>

// 处理器状态（和项目里的 FactoryStatus 一一对应）
enum class ProcessorStatus {
    IDLE,     // 空闲
    RUNNING,  // 运行中
    EXIT      // 退出
};

class Processor {
public:
    Processor();
    ~Processor();

    // 提交一个任务（主线程调用）
    void submit(TaskType type, const std::string& name);

    // 启动工作线程
    void start();

    // 停止工作线程
    void stop();

private:
    // 工作线程的主循环（在子线程中运行）
    void worker_loop();

private:
    std::atomic<ProcessorStatus>    _status;        // 线程状态（原子变量）
    BlockingQueue<std::unique_ptr<Task>> _queue;    // 任务队列
    std::unique_ptr<std::thread>    _worker;        // 工作线程
};

#endif // PROCESSOR_H
```

### 请手敲实现文件 `src/processor.cpp`

```cpp
#include "processor.h"
#include <iostream>

Processor::Processor()
    : _status(ProcessorStatus::IDLE),
      _queue(50) {}  // 队列容量50

Processor::~Processor() {
    stop();  // 析构时确保线程退出
}

void Processor::submit(TaskType type, const std::string& name) {
    // 用工厂创建任务
    auto task = TaskFactory::create_task(type, name);
    if (task) {
        _queue.put(std::move(task));  // 放入阻塞队列
        std::cout << "[Producer] 提交任务: " << name << std::endl;
    }
}

void Processor::start() {
    if (_status != ProcessorStatus::IDLE) {
        std::cerr << "[Processor] 不在 IDLE 状态，无法启动!" << std::endl;
        return;
    }
    _status = ProcessorStatus::RUNNING;

    // ★ 关键：创建工作线程，绑定到 worker_loop 方法
    // 和项目里 _working_thread = std::make_unique<std::thread>(&TrafficFlowFactory::detect, this) 一样
    _worker = std::make_unique<std::thread>(&Processor::worker_loop, this);
    std::cout << "[Processor] 工作线程已启动" << std::endl;
}

void Processor::stop() {
    if (_status != ProcessorStatus::RUNNING) {
        return;
    }
    _status = ProcessorStatus::EXIT;

    // 放入一个"毒丸"任务，唤醒可能正在等待的工作线程
    // 因为 take() 会阻塞，如果不唤醒它，join() 会永远等待
    // 技巧：put 一个 nullptr 作为退出信号
    _queue.put(nullptr);

    if (_worker && _worker->joinable()) {
        _worker->join();  // 等待工作线程结束
        std::cout << "[Processor] 工作线程已退出" << std::endl;
    }
}

void Processor::worker_loop() {
    // ★ 这就是项目里 detect() 方法的简化版
    // while 循环 + take() 阻塞等待 + 处理任务
    while (_status == ProcessorStatus::RUNNING) {
        auto task = _queue.take();  // 阻塞等待，没任务时在这里睡觉

        // nullptr 是退出信号（毒丸模式）
        if (task == nullptr) {
            std::cout << "[Worker] 收到退出信号" << std::endl;
            break;
        }

        // 执行任务
        std::cout << "[Worker] 处理任务: " << task->get_name()
                  << " (类型: " << static_cast<int>(task->get_type()) << ")"
                  << std::endl;
        task->execute();
    }
}
```

### 检查要点
- [ ] `_status` 用 `std::atomic`，读写不需要加锁
- [ ] 构造函数初始化状态为 `IDLE`
- [ ] `start()` 里用 `std::thread` 启动 `worker_loop`
- [ ] `stop()` 里先设状态为 `EXIT`，再放毒丸，最后 `join()`
- [ ] `worker_loop()` 里用 `while` 循环 + `take()` 阻塞消费

## 第 5 步：主程序 — `src/main.cpp`

### 请手敲以下代码

```cpp
#include "processor.h"
#include <iostream>
#include <chrono>
#include <thread>

int main() {
    std::cout << "===== 任务处理系统启动 =====" << std::endl;

    Processor processor;

    // 1. 启动工作线程
    processor.start();

    // 2. 模拟生产任务（主线程就是生产者）
    std::this_thread::sleep_for(std::chrono::milliseconds(100)); // 等一下让线程启动

    processor.submit(TaskType::COUNT, "计数任务A");
    processor.submit(TaskType::SUM, "求和任务B");
    processor.submit(TaskType::COUNT, "计数任务C");
    processor.submit(TaskType::SUM, "求和任务D");

    // 3. 等所有任务处理完
    std::this_thread::sleep_for(std::chrono::seconds(1));

    // 4. 停止处理器
    processor.stop();

    std::cout << "===== 任务处理系统结束 =====" << std::endl;
    return 0;
}
```

## 面试速记卡片

### 工厂模式怎么说？
> "我用了一个静态工厂方法，根据枚举类型 switch-case 创建不同的任务对象，返回基类指针。好处是新增任务类型只需要改工厂方法和枚举，调用者代码不用动，符合开闭原则。"

### 多线程怎么说？
> "主线程是生产者，往阻塞队列里放任务；工作线程是消费者，用 while 循环从队列 take 任务。退出时先设置 atomic 状态标志，再放一个 nullptr 毒丸唤醒阻塞的 take()，最后 join 等待线程结束。"

### 锁怎么说？
> "阻塞队列内部用 mutex + condition_variable 实现线程安全。put 时加锁写数据再 notify_one；take 时用 while 循环 + wait 阻塞等待。用 unique_lock 是因为 wait 需要能自动解锁和重新加锁。用 while 不用 if 是为了防止虚假唤醒。"

### RAII 怎么说？
> "lock_guard 和 unique_lock 都是 RAII 风格的智能锁。构造时自动加锁，析构时自动解锁。即使中间代码 return 或抛异常，栈上的锁对象也会自动析构释放锁，不会死锁。"
